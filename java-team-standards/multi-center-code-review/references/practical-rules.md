# 可执行规则：编码与审查共用

版本 2.8.0。这里把已有规范转换为可检查的最小规则；完整依据见 [系统与多中台规范](standards.md)。示例类型/方法是局部示意，除参考工程外不代表能直接编译。规则由项目采纳后生效，已确认业务契约优先；无法从源码确认的政策列为待核实。

执行前读取目标工程规则：对象形式、访问器、Serializable、HTTP 参数阈值、响应/分页包装、注释格式及表结构默认，仅对已采纳它们的工程生效。目标已确认规范覆盖这些默认，不覆盖参数校验、授权、持久化并发保护与契约兼容。跨工程差异按包内 [第 9 节适配](java-project-practices.md#9-多中台工程规则与公共组件) 执行，不依赖作者的本机目录或私有资料，也不移植其他项目的专项决策。

## REQ-001：需求与实现、验收必须对应

**适用**：新增或改变业务行为，以及进度/待确认事项梳理，尤其是跨模块、多个场景或政策相关需求。**要求**：先用已有需求、契约和会话确认输入、主体范围、期望行为及验收；小需求在回复中简短说明，复杂需求复用已有需求/任务文档。缺少规则时区分歧义、缺口、冲突和实施假设；金额、权限及恢复政策不能靠行业经验批准。

- 反例：需求只说“支持恢复”，实现自行选择恢复关联数据、覆盖新记录；仅凭新增了接口就宣布完成。
- 正例：管理表恢复沿既有政策核验权限和占号冲突；对应恢复、无权、冲突三个场景及本次修改点，未知的关联恢复政策单列待确认。
- 验收：每项已确认需求都有实施或明确未完成说明及对应证据；没有遗漏边界/失败语义，也没有无需求依据的额外实现。缺文档不等于代码有缺陷，需求质量检查不代替行为验证。
- 例外：已有验收条目直接引用，不另造 spec/plan/tasks 三套文档；普通可逆实现选择沿用项目默认并说明假设，已获授权的独立工作继续推进。

进度梳理按 [Java 项目实践第 7 节](java-project-practices.md#7-对照工程推进进度与逐点确认)对照技术目标、实际代码和当前验证，先落实已确认且独立的工作。复杂待确认项拆到单个字段、接口、状态或政策，记录编号、依据/缺口、所需答案与阻断代码/能力；区分业务决策、协议缺口、环境参数和已确认暂缓。用户已答复“尚未确认”或要求先做确定部分时，本轮不重复追问同项；用户恢复逐项处理或新证据改变问题时再围绕具体阻断确认。高风险入口仍遵守已确认的启停边界，不用假默认值填空。

## BUG-001：修复前建立失败证据，修复后用原断言复验

**适用**：缺陷修复、失败测试、性能回归。**要求**：记录运行版本、环境、触发输入、实际与预期结果；先复现或取得足以定位的错误/调用证据，再沿入口、数据来源及相关调用方定位根因。一次检验一个明确假设，不叠加未经验证的修补。

- 反例：看到分页异常只改 Controller 默认值；未核验内部调用和偏移计算，就以编译成功报告修复。
- 正例：相同大页码在旧实现产生错误结果，查明偏移乘法溢出后在共享计算点修复，并用原页码断言与正常分页复验。
- 验收：修复前失败证据、根因、修改点和修复后同一断言可对应；相关调用方及正常边界未退化。性能回归使用同一负载/数据范围的前后指标，不用单次体感判断。重复失败时重新核验假设、配置和实际运行制品，不自动扩大为架构重构。
- 例外：确定的编译错误可用原编译失败作为证据，不另造测试框架；偶发/外部问题记录无法复现条件和缺少证据，完成已授权的独立工作，不能将缓解措施报告为已证明根因修复。临时验证按项目要求仅保留本地。

## CONFIG-001：配置要实际绑定、校验并按部署方式生效

**适用**：新增/修改配置组、绑定代码、profile、环境变量或轮换方式。**要求**：读取已有键名与部署配置，优先复用当前绑定方式；配置组采用项目已用的类型化绑定，核验注册、校验提供者及嵌套校验。单值配置不机械重写。单位和上限明确，关键凭据/端点缺失时拒绝启动或按已确认政策禁用，不填教学默认值。

- 反例：声明配置类却未注册；只用 @NotNull 校验 Duration，就以为零/负超时也被拒绝；配置文件改了便声称线上已刷新。
- 正例：在实际 profile 和环境变量覆盖路径下验证超时为正、嵌套端点有效；复用已有校验或 JDK 不变量检查，记录需要重启还是采用既有刷新/轮换机制。
- 验收：有效配置、缺失/非法关键值、嵌套约束、单位转换及部署覆盖各有证据；未连实际环境时明确边界。重命名键同步部署调用方，敏感配置不经 toString、日志或管理端点泄漏。BOM、包名及注解遵循实际工程版本，不混用 Boot 3/4 样例。
- 例外：配置已由现有设施校验时直接验证其实际路径；不为一个开关增加框架或依赖。远端配置不在权限内时列明未验证项，不擅自写线上配置。

- 前后端连接配置追加 [完整规范 11.2.1](standards.md#1121-前后端连接配置与环境边界)：核对 API 基址、端口/代理路径与各环境来源，公开配置不携带服务端秘密；允许/拒绝 Origin、预检与凭据在实际业务入口验证，不以健康页证明完整安全链。生产缺失配置不能落到示例账户/密码，未连浏览器或部署环境明确未验证。

## INIT-001：以已确认决策创建最小工程

**适用**：新建工程、增设服务/依赖、技术栈组合调整或工程模板更新。**要求**：先记录技术版本、部署形态和需求依据；未定数据库和领域不生成空模块。

- 反例：为了“多中台”先创建 payment、account、settlement 三套空服务，并强制引入 Redis/MQ。
- 正例：先建一个部署单元和一个业务切片；边界确有独立演进或容量需求时再拆。
- 验收：构建文件与决策一致，每个新增依赖都有实际调用；应用能启动。调整依赖/插件时按完整规范 3.6、16.5 核对依赖树、有效 POM、scope、固定制品和真实生命周期，不凭版本管理声明推定已引入或检查已执行。只交方案时不以缺少代码报错。
- 例外：已有组织技术基线直接继承并标来源，不重复选型。

- 技术栈组合追加 [3.7](standards.md#37-技术栈组合与生成结果一致)：区分技术兼容与生成器范围，选择/保存配置/产物一致；受影响合法与冲突组合各有验收，不静默移除已确认认证等能力。普通需求不维护全技术目录。
- 实际模板更新追加 [3.8](standards.md#38-工程模板的基线更新与恢复)：记录来源、输入和落盘基线，先展示差异；保护本地修改/删除/重命名，计划变化后复查，失败或中断可恢复本次仍拥有的内容。无可信基线不伪造，跨版本支持须验证实际分发版本，不借规范安装运行生成器。

## ARCH-001：模块通过公开契约协作，边界要有验证

**适用**：新增/调整模块、跨模块调用、复杂用例分层或用户要求的包/资源归类。**要求**：先读 [Java 项目实践](java-project-practices.md)第 1～2 节，包移动再读第 8 节；列明公开入口、内部实现、允许依赖和写入责任；简单 CRUD 保留 Service + Mapper，逻辑模块不强拆部署。

- 反例：Controller 调用另一模块 Mapper；把循环依赖搬进 CommonService；创建五个空 Maven 模块后宣称采用 DDD。
- 正例：同进程调用最小公开契约，外部 SDK 由适配器隔离；业务规则在同一用例中复用，不向调用方暴露内部 DO/Wrapper。真实边界需要的端口可以有单实现，普通内部服务不机械加接口。
- 验收：追踪实际 import、调用和构建依赖；已有架构工具时用临时越界/循环样例证明门禁失败、恢复后通过。列出检测范围；不能把空测试、注释断言或只检查包名视为门禁。
- 例外：存量混合架构按获准范围渐进调整，记录具体依赖边；不因参考 COLA 就批量重构。

用户要求目录归类时，按 [包移动验收](java-project-practices.md#8-按业务归属整理包与资源)保持既有分层，在实际业务范围内归属 DTO、VO、Mapper、Repository 和资源；不为目录拆用例或无必要地扩大 public。同步 package/import、扫描根包、XML namespace/resultType、资源加载与测试/文档；使用干净构建验证无旧类残留，实际装配确认预期 Mapper/语句都存在，零文件检查不能判通过。包名涉及对象流、类型元数据或跨模块公开契约时，按 SERIAL-001 评估兼容性。

## EXT-001：策略选择必须明确，默认回退不能靠猜

**适用**：多渠道、多产品、多政策实现及扩展注册。**要求**：先读 [Java 项目实践](java-project-practices.md)第 3 节；已有真实差异才抽扩展点，复用现有分支或策略机制。选择键来自可信上下文，统一执行授权、幂等与审计。

- 反例：找不到支付渠道就走任意默认通道；重复注册后者覆盖前者；单例策略把当前租户写进成员字段。
- 正例：固定注册表拒绝重复键，明确无匹配错误；只有获准且语义等价时回退。进行中的副作用固定策略版本/关键快照，超时沿原操作查证。
- 验收：精确匹配、无匹配、重复配置、越权选择、策略异常、配置变更与并发隔离；核验真实组件的默认查找行为，不只看接口名称。
- 例外：少量稳定分支不必引入策略接口；没有需求不引入 COLA 扩展组件或自建插件平台。

## JAVA-001：基础 API 的边界必须符合业务语义

**适用**：本次新增/修改的值比较、精确计算、对象约束、时间、集合、排序、控制流和资源处理。**要求**：按 [完整规范第 5 节](standards.md#5-java-基础与异常处理) 选择细则；保留 null、单位、顺序、可变性与异常契约，优先 JDK/项目已有能力，不为通用细则重写工具库。

```java
// 反例：业务公历日期用 YYYY；默认 SMART 解析悄悄调整非法日期。
// 正例：严格公历日期；以下为局部示意，调用方须处理非法输入。
DateTimeFormatter format = DateTimeFormatter.ofPattern("uuuu-MM-dd")
        .withResolverStyle(ResolverStyle.STRICT);
LocalDate date = LocalDate.parse(input, format);

// 反例：(left, right) -> left - right，极值相减会溢出。
// 正例：按实际类型比较；并列/null 政策另按业务补充。
Comparator<Integer> order = Integer::compare;
```

验收：日期至少覆盖跨周所属年、合法/非法闰日；排序覆盖 MIN_VALUE/0/MAX_VALUE 及实际并列/null；涉及金额检查精确输入、scale/rounding；涉及集合验证真实调用方修改、数组/视图、重复键/null；涉及异常验证原失败与资源释放。具体输入与断言见完整规范 5.5，执行证据与未覆盖项分别记录，不机械跑每一行。

例外：旧日期类型可留在适配边界；可空值不一律默认 false/0；既定只读集合不强改 ArrayList；外部字段/枚举兼容政策优先。细则缺失只能提示实际风险，不能将 API 名字本身当缺陷。

## WEB-001：Web 请求与响应边界

**适用**：JSON/表单 Web 业务接口。**要求**：Controller 做输入校验、边界转换和入口编排；Service 执行业务。业务请求使用目标 Query，业务对象响应使用 VO；允许已确认的标量入口、基础类型、统一响应和 ORM 无关公共分页包装。DTO、DO 不直接成为 Web 契约。简单用例可拆成已校验业务参数，不为转换增加无用途 DTO/Converter。对象形式、访问器及可变性沿目标 class/record 约定；class + Lombok 的具体做法见完整规范 4.2。注释按目标采纳的 4.3 要求准确说明业务、状态取值、金额单位及展示来源；不机械补未采纳的 Javadoc 标签。

```java
// 反例：直接暴露内部 DTO，后续内部字段变化会改变公共响应。
public OrganizationDTO detail(OrganizationDTO request) { ... }

/**
 * POST /api/reference/organizations/page：只读查询当前主体可见的组织。
 * JSON 空对象使用页码 1、每页 20 条，上限 100；缺失/非法请求体或校验失败返回 400，
 * 媒体类型不支持返回 415。认证和适用的 CSRF 由安全链处理，动作及资源权限由服务校验。
 *
 * @param query 经绑定和校验的分页 Query，不包含可由客户端修改的授权范围
 * @param authentication 框架提供的认证身份
 * @return 可见组织及同范围 total；越过末页返回空 items，保留 total
 */
@PostMapping("/page") // 所在 Controller 的类级路径为 /api/reference/organizations
public ApiResponseVO<OrganizationPageVO> page(
        @Valid @RequestBody OrganizationPageQuery query, Authentication authentication) {
    OrganizationPageDTO page = service.page(new OrganizationPageQueryDTO(query.getPageNo(), query.getPageSize()),
        identities.caller(authentication));
    return ApiResponseVO.ok(new OrganizationPageVO(page.getItems().stream().map(this::toVO).toList(),
        page.getTotal(), page.getPageNo(), page.getPageSize()));
}
```

HTTP 方法先遵循操作语义及目标已确认契约。仅已采纳完整规范 6.2 参数数量约定时，业务请求参数超过 3 个使用 POST + @Valid @RequestBody，3 个及以内的简单只读查询可用 GET + @ModelAttribute；可选项、分页及继承字段计入，认证/CSRF/追踪信息不计入，复杂结构按 6.2 处理。上例保留参考工程已确认的 POST 契约，不代表其他工程必须采用该阈值或批量改造既有接口。按实际方法验证绑定、默认值、错误、415 与适用的 CSRF，不能仅因分页使用 GET、更新使用 PUT 或参数数量不同报错。

验收：检查 Controller 签名和实际 JSON，不含内部企业范围、ORM 字段或持久层分页对象；缺参走校验错误。转换可用已有工具，不能为几个字段强加转换框架。

例外：文件下载、流式输出、第三方既定回调按已确认协议，不强包 VO；记录原因与契约验证。

## SERIAL-001：序列化能力和线上的协议分别验证

**适用**：Query/DTO/VO、RPC 请求响应、消息和缓存值。**要求**：先核验目标已采纳规则与真实序列化器。已采纳 Serializable 团队约定或使用 Java 对象流的类型实现接口，并按对应规则声明自己的 `@Serial private static final long serialVersionUID = 1L;`；JDK 低于 14 时省略 @Serial。纯 JSON、HTTP 或未采用该约定的工程不机械增加 Serializable/UID。下例演示已采纳该团队约定的 class，不限制目标已确认的 record；真实绑定、对象图和新旧读取分别验证。

```java
/** 按稳定组织标识查询当前主体有权访问的组织。 */
@Getter
@Setter
public class OrganizationDetailQuery implements Serializable {
    /** Java 对象流的类版本；兼容演进时保持稳定。 */
    @Serial
    private static final long serialVersionUID = 1L;

    /** 稳定组织标识。 */
    @NotBlank
    private String organizationId;
}
```

上例省略 import。已有合适的 BaseQuery/BaseRequest 可以复用；每个可序列化子类仍声明自己的 UID，不把父类 UID 当成全继承树版本。没有公共字段或行为时可直接实现接口，不为消除标记重复建立空继承层。

- 反例：只在父类写 UID；给包装类加 Serializable 就假设任意泛型 payload 都可序列化；为了改 getter 或加可选字段机械递增 UID。
- 正例：类型及整个非 transient 对象图都满足所选序列化器要求，嵌套 DTO、集合元素和实际泛型类型一并验证。兼容改动维持 UID；破坏性变更先设计新旧读取、缓存失效或迁移策略，不能只改版本号。
- JSON 出参用 getter 暴露约定字段；入参需无参构造和 setter，或显式 Jackson creator/property 映射。不能用 `@NoArgsConstructor(force = true)` 绕过 final 字段和构造校验。仅作为输出的 VO 不必为了并不存在的反序列化需求增加 setter。
- 泛型 JSON 反序列化保留 `TypeReference`/`JavaType`，不能只传裸包装类。字段名称、时间/时区、枚举、BigDecimal、超出 JavaScript 安全整数范围的 ID，以及缺失/null/未知字段策略按实际契约固定。
- `serialVersionUID` 不控制 JSON/RPC schema，Serializable 不等于所有 RPC 序列化器兼容；依据实际 Dubbo/HTTP、消息、Redis 序列化配置验证，不能从文件名推断协议。
- `transient` 的 Java 语义不能代替 JSON 的字段隔离策略；敏感字段分别按序列化器显式排除并验证。服务端 CallerDTO 等身份上下文只能由可信认证关系建立，可序列化不代表可以信任客户端反序列化结果。
- 不对外部不可信字节启用 Java 原生反序列化。原生反序列化通常不调用 Serializable 类的普通构造方法；构造校验、默认值和防御性复制不能当成该入口的安全保障。确有业务需求时限定类/深度/大小并验证恢复后的不变量，或采用能验证输入的明确协议。

**验收**：使用实际 ObjectMapper 核验 Web 字段、Query 默认值和校验；实际采用 Java 对象流时，在隔离环境用本地产生的可信对象往返，测试嵌套集合及非 Serializable payload 失败。实际用到 RPC、缓存或事件时测对应序列化器及新旧交叉读取；一次同版本往返不证明升级兼容。

**例外**：纯领域实体、基础设施对象不因“可能传输”自动加 Serializable；已有项目不采用本约定时按其真实契约评估，不强迫为 JSON 添加继承层。

## WEB-002：分页有边界、有稳定顺序

**适用**：列表和分页导出。**要求**：HTTP 方法先按目标契约；仅采用参数数量约定时按完整规范 6.2 选择 POST/GET，查询本身只读。页码起点、默认值、最大值和超限行为先在契约确定；沿用分页 Query 与目标分页 VO，或 ORM 无关的公共分页结构包裹 VO，不直接暴露内部分页 DTO/IPage。total 与 items 使用同一权限和筛选条件。复杂条件增加长度、集合大小、嵌套校验和排序字段白名单，不能因放进 JSON 就免于限制。

```java
// 反例：不校验大小；先全库计数，再只过滤本页，会泄漏总数并产生空页。
return new PageVO<>(filterForCaller(repository.findAll()), repository.countAll(), pageNo, pageSize);

// 正例：先按可信主体限制数据，再计数和分页；乘法先升为 long 防溢出。
long offset = ((long) query.getPageNo() - 1) * query.getPageSize();
// SQL 场景：items 和 count 共用企业及业务过滤条件，ORDER BY create_time DESC, id DESC。
```

**验收**：先满足认证及适用的 CSRF 前置条件，再检查绑定和业务行为；默认值以项目契约为准，不能直接把示例数值视为生产要求。

| 输入或场景 | 预期与检查点 |
| --- | --- |
| 参数数量和结构 | 先核验目标 HTTP 契约；已采纳数量约定时统计完整业务字段，复杂结构按 6.2；字段少不免除大小限制 |
| GET 缺省/空查询参数；POST `{}`、字段缺失/null | 按实际绑定方式验证默认值或拒绝行为；GET 不依赖请求体，POST 缺失请求体不等于空对象 |
| 0/负数、超上限、不可绑定的非数字 | 返回约定的 400 错误体；POST 同时核验 ObjectMapper 的数字/字符串强制转换策略 |
| POST 缺失请求体、非法 JSON、不支持的 Content-Type | 分别验证 400、400、415；不机械套给 GET 接口 |
| 错误 HTTP 方法 | 返回 405；路径仅声明 POST 时核验 GET 不进入用例，反之亦然 |
| 极大页码、末页、同创建时间 | offset 不溢出；越界 items 为空但 total 正确；排序带唯一键 |
| 两个企业、组合筛选、不同动作权限 | items 与 total 范围一致；客户端参数不能扩大授权范围 |
| GET 改 POST 或调整请求结构 | 同步调用方、接口文档和安全验证，按已确认契约安排迁移 |

稳定排序不承诺并发写入下 offset 分页的快照一致性，强一致遍历另选游标/快照方案。数据库查询应下推筛选、排序、计数和分页；参考工程的少量固定数据内存分页不是生产大表方案。

例外：历史接口保持已公布契约，改变限制或排序先评估兼容性。

## WEB-003：前后端协议按真实报文验收

**适用**：新增/修改浏览器接口、响应字段、客户端解析、HTTP 头、请求上限或跳转。**要求**：按 [完整规范 6.4～6.6](standards.md#64-前后端-json-与字段契约) 明确 UTF-8/媒体类型、稳定字段类型、日期/时区、ID/金额精度、空值、状态/错误及兼容；按实际行为追加 WEB-001/002、SERIAL-001、ERR-001、AUTH-001、IDEM-001。前端校验和按钮防抖不替代后端校验、权限与幂等。

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "id": "9007199254740993",
    "amount": "0.10",
    "occurredAt": "2026-09-30T10:00:00+08:00"
  }
}
```

正例中的 amount 需在对应 VO/接口文档注明如“单位元，2 位小数”；这是沿已有包装的示意，不批准新业务金额字段。反例：ID 先输出为 JS number 或前端转 Number 再传回；无偏移时间点靠浏览器猜时区；同字段时而数字时而字符串；403 无限刷新登录；错误/空结果混用；任意 URL 跳转；204 后强制 response.json()。

验收：检查实际状态/Content-Type/头和 JSON，再用项目 JS/浏览器往返该 ID、日期与金额；覆盖空列表、字段缺失/null、未知枚举/字段、正常与绑定/权限/基础设施错误、适用的 202/204/下载。请求上限在真实网关/解析路径验证边界和上限 + 1；敏感响应核验 no-store 的设施行为，跳转校验真实解析目标，用户内容不执行脚本。具体断言见完整规范 6.6；只测 ObjectMapper 不算全链路证明。

例外：已有 snake_case、时间戳或 HTTP 200 + 业务错误等公共契约先保兼容、明确迁移，不能因新默认立即破坏客户端；第三方回调、上传/下载、流式协议按实际契约，不强套 JSON 包装；无缓存/跳转能力时不为验收新增设施。GET/POST 沿 6.2 的业务参数计数，不因本规则强改全部分页。

已采用接口/客户端代码生成时追加 [完整规范 6.7](standards.md#67-已采用接口代码生成时的契约验收)：确定权威输入与工具版本，干净重新生成并验证实际消费方编译、差异与真实字段/错误。生成类型仍遵守 WEB-001，默认接口/注解不算业务完成；未采用时不引入生成器，生成服务端代码不等于前端联调通过。

## ERR-001：错误有类型，不泄漏内部信息

**适用**：Web 和服务边界。**要求**：区分参数、未认证、无权、不存在和系统故障；不能用 HTTP 200 掩盖失败。明确安全消息、稳定错误码及关联方式。

```java
// 反例：return ApiResponseVO.ok(exception.getMessage());
// 正例：参数错误返回 400 + INVALID_ARGUMENT，系统异常返回 500 + INTERNAL_ERROR。
// 未预期异常在统一边界记录一次堆栈；对外只给固定安全提示。
```

验收：HTTP 状态与错误体一致，分别覆盖 JSON 解析/参数校验 400、未认证 401、权限拒绝 403、资源不存在 404、方法不支持 405、媒体类型不支持 415 及系统故障 500；响应不含 SQL、堆栈、密码、Token 或内部路径。安全过滤链的 401/403 也遵守错误契约。认证、CSRF、路由和绑定存在执行先后，多项同时失败时按实际链路判断，不能一律断言匿名 POST 必须返回 401。不得吞异常后继续提交不完整业务。

例外：外部协议指定响应格式时按协议适配，保留内部分类和观测。

## AUTH-001：登录不等于有权，角色不等于资源归属

**适用**：受保护的详情、列表、写入、导出和异步执行。**要求**：身份来自验证后的会话/凭证，企业范围来自可信授权关系；不能信任客户端传入的企业 ID 作为权限证明。动作权限和资源归属都检查。

```java
// 反例：repository.findById(query.getId()); // 只判断已登录
// 正例：先检查 organization:read，再按 id + caller.getEnterpriseId() 查询。
// 列表、总数、缓存键、任务执行上下文同样包含有效资源范围。
```

验收：匿名、无动作权限、同企业、跨企业、不存在资源；示例将跨企业和不存在统一为 404，实际项目采用已确认的防枚举政策。后台任务不能因为没有 HTTP Controller 就跳过授权依据。

使用 Cookie、HTTP Basic 等浏览器自动附带凭证时，核验适用的 CSRF 保护：缺失/错误令牌应拒绝，有效凭证与令牌可连续完成请求；令牌轮换或会话变化按真实策略验证。CSRF 令牌不是身份凭证，不能单凭令牌取得身份；Cookie 是否承载登录身份由项目认证方案决定。不得为了切换 POST 全局关闭 CSRF。参考工程的 Basic、令牌获取路径和安全上下文存储配置仅为教学实现，不要求生产项目照搬。

修改浏览器跨域或安全过滤链时，追加合法/非法 Origin 的预检与实际请求验证：核对来源、方法、请求头及凭证策略，带凭证的来源限制不能以通配或任意反射 Origin 绕过；核验 CORS 与认证的执行顺序。CORS 不替代身份和资源授权，HTTP 200 不代表浏览器允许跨域。按返回内容与浏览器风险评估适用安全响应头，不统一照搬第三方 CSP/CSRF 配置。

已接入管理端点或本次改变暴露范围时，逐项核验端点、网络入口、安全链及角色；env、configprops、heapdump、日志配置等敏感能力不能因独立端口或内网就默认公开，脱敏另按 OBS-001 验证。登录、公开高成本接口有实际滥用风险时复用已有网关/限流并验证拒绝语义，不为普通 CRUD 自动引入限流库。

例外：明确公开数据列入公开清单；不能用管理员名称或前端隐藏按钮替代服务端判断。

## SQL-001：条件有界，索引有证据

**适用**：查询、导出与排查。**要求**：参数绑定、显式字段、数据范围、稳定排序；大表先对限定查询做 EXPLAIN，索引依实际过滤/排序和基数评估。

```sql
-- 反例：SELECT * FROM organization ORDER BY create_time DESC;
-- 正例：仅作结构示意；执行前确认库、表、字段和绑定值。
SELECT id, display_name, create_time
FROM organization
WHERE enterprise_id = :trusted_enterprise_id
ORDER BY create_time DESC, id DESC
LIMIT 20;
```

验收：没有字符串拼接注入；items/count 口径一致；说明扫描量和排序行为。数据库连接仅只读；写入/迁移脚本先按完整规范 10.2 提供影响数、LIMIT 20 样例和冲突预检。不能把内存查询演示当成 SQL 已验证。

聚合/ORM 验收追加 [完整规范 10.4](standards.md#104-sql-聚合与-orm-映射)、16.5：COUNT(*)/COUNT(column)、无行/全 null 的 SUM、LEFT JOIN 无子项；真实驱动的 Long/BigDecimal/时间及别名映射；缺失/null/清空与更新策略；值绑定和动态标识符白名单。固定材料 E20 只作评审输入，不替代实际数据库验证。

例外：小表合理全扫不自动判为缺陷；以数据量、计划和成本判断。规范不自动授权建索引。

## DDL-001：先确定业务与字段语义，再生成表结构

**适用**：MySQL 表设计、CREATE/ALTER、初始化或迁移脚本，以及逻辑删除/恢复实现。**要求**：涉及结构时先读取 [MySQL 建表规范](mysql-schema.md)，按已确认版本和现有约定输出表职责、字段字典、唯一性与索引依据，再生成 SQL。每表每列 COMMENT 必须说明业务含义，金额单位、时间语义、状态取值准确；默认不建物理外键、不用级联删除或业务触发器，例外记录依据及验证。只实现删除/恢复时读取第 4.1、6 节，不因此生成额外 DDL。

- 反例：把逻辑表清单直接转成物理表；业务号全用 VARCHAR(255)、金额用 DOUBLE、注释只有“状态”；新内部 ID 仍用 AUTO_INCREMENT，或按 id/no/ref 字段名批量加 ascii_bin；为了兼容 5.7 给每张表加触发器，或仅保留不生效的 CHECK。
- 正例：新内部 ID 用 BIGINT/Java Long 雪花 ID，不自增；公共时间列 create_time/update_time，字符串默认继承表级 utf8mb4_general_ci，列级例外有契约依据。按真实主体范围设置非空业务唯一键，保持既有金额单位、主键和比较契约，核验大小写/尾空格下应用与数据库幂等判断一致；5.7 使用应用校验、原子条件写入和必要唯一约束，8.0.16+ 的 CHECK 仅作行级增强。
- 验收：核对大小写/尾空格及 NULL 唯一性、逻辑删除后业务号复用、ID 映射、对象冲突及存量预检；同时核对行宽/索引字节预算、隐含主键索引、严格模式与应用连接配置；外部经验值按建表规范第 12 节的适用边界处理。实际建表在获准隔离实例核验 SHOW CREATE TABLE/索引、非法值、并发与回滚。只做文档或静态检查时明确未执行 DDL，不能宣称两版 MySQL 均通过。
- 例外：目标项目已经确认的命名、ID、外键等约定优先，说明差异和替代保护；不据通用模板自动重建存量表。只要求方案/SQL 不等于授权执行，初始化冲突不自动删除清场。

逻辑删除采用 `deleted`、0 未删除/1 已删除；存量命名不自动迁移，支付与审计事实不机械加列。按 [第 4.1 节](mysql-schema.md#41-逻辑删除字段读写与恢复)验收查询/total/导出及自写 SQL、LEFT JOIN、权限、重复删除、恢复占号、普通更新竞争与审计/缓存同步。仅添加 `@TableLogic`，或把 deleted 拼入唯一键，都不构成验收通过。

## REDIS-001：按用途核验生命周期、原子边界与恢复

**适用**：实际使用 Redis 的 Key/缓存、序列化与客户端、命令/脚本、锁、计数、Stream 及部署维护。**要求**：先按共用 [Redis 专项规范](redis-standards.md) 相关章节确认实际版本、拓扑、权威来源、业务范围、TTL/保留、容量、时限与恢复。项目现有设施优先，不自动加缓存、锁框架或消息组件。

- 正例：组织资料缓存按真实企业范围隔离，写值和 TTL 一次完成；提交后失效并明确陈旧/失败窗口。已有锁组件按实际租约与 owner 释放，数据库条件更新仍拒绝迟到操作；可靠 Stream 消费在业务与幂等记录提交后 ACK，PEL 恢复复用同一 eventId。
- 反例：SETNX 后另设过期；GET 校验后 DEL 解锁；扫描本批为空就结束；默认 Cache.clear 的 KEYS 清理未经容量/拓扑核验；消息先 ACK 后写事实；缓存/锁服务失败时直接批准资金操作。
- 验收：按实际变更选择专项第 10 节的命中/失效、空批与重复、租约/接管/迟到、提交与 ACK 间崩溃、容量/切换及旧协议读取场景。记录真实版本、输入与断言；源码推导、mock、真实 Redis/数据库及故障演练分开报告。
- 例外：没有 Redis 的模块不增加依赖；小集合的有界全量读取不机械报错。长期保留的 Stream/状态不套缓存 TTL，但必须有容量、清理与恢复依据。阈值、hash tag、连接池和新命令按实际版本/负载采用。

锁与持久化保护追加 CON-001、IDEM-001；消息和数据库双写追加 TX-001、REMOTE-001；配置/协议/访问/输出追加 CONFIG-001、SERIAL-001、AUTH-001、OBS-001。只核验本次实际行为，不能因只看到一个方法就断言整个系统没有补偿或去重。

## TX-001：本地事务不能回滚外部副作用

**适用**：多个本地写入或跨系统副作用。**要求**：明确事务入口、传播、回滚异常与代理是否生效；本地事实一致提交。远程操作先明确稳定请求号与恢复协议，不用长事务包住网络调用冒充原子性。

```java
// 反例：同类 this.saveInTransaction()，误以为 @Transactional 一定生效；
// 或事务内先调用银行，再认为本地 rollback 可以撤销已付款。
// 正例：经有效事务入口原子保存本地意图；外部执行沿稳定操作号查证/恢复。
```

验收：在真实选定数据库上注入第二次写失败，确认第一次回滚；覆盖“远程成功、本地失败”恢复。仅检查注解、编译或 mock 不足以证明事务。

代理核验按 [完整规范 8.1](standards.md#81-注解要经过实际代理入口)：确认受管 Bean、版本、代理模式、事务管理器及真实入口。proxy 模式下自调用不触发内层事务传播；已有外层事务仍可能有效。Spring 6.0 起默认类代理支持 protected/包可见事务方法，JDK 接口代理及 publicMethodsOnly 等配置另查，不能一律判失效。缓存/异步注解按各自文档核验，不照套事务可见性。

例外：纯只读查询无须硬加事务；跨资源需要可靠事件时再评估 Outbox，不强制引入。

## CON-001：状态修改必须校验旧状态与实际影响

**适用**：状态流转、预算、库存及并发资源修改。**要求**：数据库条件更新/版本条件保护不变量，并检查影响行数；先查再改不具备并发保护。

```java
// 反例：if (load(id).isPending()) { saveSuccess(id); }
// 正例：底层更新同时限定 id、归属及期望状态，变更计数必须恰为 1。
int affected = repository.transition(id, owner, PENDING, SUCCESS);
if (affected != 1) {
    throw new StateConflictException();
}
```

验收：并发执行两次、成功后迟到失败、同版本竞争；只能一次改变事实。扣减还需原子预算条件，0 行须按实际事实区分重复、冲突或无权，不直接当成功。

例外：无状态变化的只读能力不适用；分布式锁不能替代持久化不变量。

## IDEM-001：同号同意图，异参必须拒绝

**适用**：客户端可重试写请求、回调、任务和消费。**要求**：定义幂等作用域（主体/操作类型/操作号）、有效期、参数指纹、并发占位与结果；同键异参拒绝，同参重复返回原结果或明确处理中。

```java
// 反例：每次重试重新生成 requestId，或仅 Redis SETNX 后立刻执行不可恢复副作用。
// 正例：稳定 operationId + 持久化唯一约束；同事务登记本地事实；
// 已成功复用原结果，处理中/未知按原号恢复，不重新创建意图。
```

验收：并发同参、同键异参、执行后响应丢失、崩溃重启、记录过期后迟到重试；说明保护窗口。Redis/内存演示不能证明重启安全。

例外：无副作用查询不用幂等表；具体持久化方案随项目选型，但不能省略重复副作用保护。

## REMOTE-001：重试先有契约，再有预算

**适用**：HTTP/RPC、SDK 与消息重投。**要求**：连接/读取或总超时明确，重试层级和总预算有界；只对契约允许的瞬时故障退避并加抖动。写入沿原请求号，未知结果先查证。

```java
// 反例：catch (Exception e) { return callAgainWithNewId(); }
// 正例：参数/鉴权错误不重试；受控读操作按预算重试；
// 非幂等写入超时保存 UNKNOWN，交由原号查询或批准的恢复流程。
```

验收：连接失败、读取超时、限流、永久错误和下游已成功但响应丢失；统计实际总尝试次数，避免 SDK 与应用重试相乘。

迁移已有通道时沿入口、实际请求/查单、SDK 映射和回调核验产品、字段、原号、金额及终态证据；注释/枚举、占位查询和申请已受理不证明正式退款或实收。把旧实现的可复用事实与正式协议缺口分开；共同必要校验放在已有共享副作用入口，在派发标记/发送前执行，不能只要求调用者先校验。损坏原快照保留原号查证/人工处理，不清零已派发状态后重新下单。

例外：同步纯读可直接报可重试错误，不为每个读取建立状态机。

## OBS-001：日志够定位，敏感信息不出边界

**适用**：日志、异常、关键审计及已接入的管理端点/探针。**要求**：结构化记录操作号、主体引用、结果与耗时；不记录密码、Authorization、签名密钥、完整个人信息或任意完整请求体。关键事实审计按业务要求持久化。

```java
// 反例：log.info("request={}, headers={}", request, headers);
// 正例：log.info("operationId={} result={}", operationId, resultCode);
```

验收：用带敏感内容的失败输入检查响应与日志；一次系统异常只记录一次堆栈，能关联操作。日志参数化不自动防换行伪造，外部字符串须限制/清洗或结构化编码。

本次涉及管理端点、探针或配置诊断时，结合 AUTH-001 核验可访问范围及实际输出；使用虚构凭据检查脱敏，不打印真实环境变量值或全量绑定配置。健康详情不暴露敏感配置；liveness 不因普通远端故障触发循环重启，readiness 与是否接收流量的实际政策对应。未接入观测组件时不为满足本规则新增依赖。

例外：示例只读工程没有关键写事实，不能声称已实现生产审计体系。

常用日志验收见完整规范 14.1、16.5：关闭 debug 时昂贵参数不求值、异常责任边界不重复、滚动/采集容量与政策、虚构敏感值及换行；标准日志输出 stdout 可用，不与直接 System.out 混淆。保留期由已确认政策决定，不机械复制上游示例天数。

## CHECK-001：检查必须执行，报告必须分层

**适用**：所有交付。**要求**：使用实际构建配置的命令，选择与变更相关的验证；不机械运行无关测试或跳过失败后宣称通过。

- 反例：`mvn -DskipTests package` 后写“测试通过，生产可用”。
- 正例：报告“主代码编译通过；Checkstyle 通过；实际 HTTP 断言 N 项通过；无数据库，事务/幂等未验证”。
- 验收：命令、退出码、断言数量与结果可复核；静态门禁要以一个故意违规样例验证确实失败，随后恢复。临时测试是否入库遵循项目要求。
- 交付对应需求/规则、实际修改点、验证证据与未覆盖项；小改动简短说明，复杂变更再列表。缺陷修复追加 BUG-001 的前后对照，配置变更追加 CONFIG-001 的实际覆盖检查，未运行项不算通过。
- 改集合返回值或收集 API 时按 [完整规范 15.1](standards.md#151-集合与-stream-调整要保留可变性契约)核验实际修改调用方、空集合及顺序/null 契约；Stream.toList 不可修改，Collectors.toList 不保证可变性。不以编译成功或更短语法证明行为兼容，也不为只读集合增加无需求副本。
- 自动化范围：参考工程的 Checkstyle 只覆盖导入、花括号、空 catch、缩进、行宽及手写方法 Javadoc 存在性和参数/返回标签；注释是否准确表达业务仍需人工或智能体核对；本页业务规则依赖契约验证、实际测试及审查，不能宣称已全部被 CI 强制执行。
- 分层验证：按 [Java 项目实践第 5 节](java-project-practices.md#5-测试证明什么就报告什么)选择纯规则、Web、存储、模块或协议验证；涉及提交后监听时覆盖真实提交/重启，检查门禁是否实际绑定。测试文件遵循项目仅本地验证、不提交的要求，不报告不存在的 CI 回归。
- 进度与结构调整追加第 7～8 节的证据：记录组件实现、实际装配/本地验证、真实联调与上线验收各自状态；汇总当轮测试报告的通过/失败/错误/跳过及跳过原因，不沿用上一轮数量。检查预期文件/Mapper 数量及旧产物残留，不能以“目录移动完”证明行为、权限或事务不变。
- Skill 收益另做固定输入与基线评测：客户端发现、模型遵循和生成代码行为分别验证；记录模型/客户端版本、源码提交、工作区状态、判定证据及失败。命令成功退出只证明采集完成，主动提供规则的评测不证明自动发现。方案见开发 Skill 的初始化指南，材料见本包 evaluations/README.md；不随日常任务自动调用模型或生成评测工程。
- 例外：文档变更验证引用和包一致性即可，不编造 Java 测试。没有真实环境时明确未验证项。
- 能力证据与实际交付制品按 [完整规范 16.6](standards.md#166-能力证据等级与交付制品)：定义/生成/构建/运行分别报告，真实联调与上线另列；记录版本、输入、制品、环境和断言范围，变更后复验受影响能力。健康页、H2/mock、配置命令或旧收据不能提升未覆盖结论；交付工程验证实际 ZIP/JAR/发布包，仅规范文档按包检查验收。
