# 系统与多中台 Java 开发规范

版本：v2.7.0 可复用团队基线。来源版本日期：2026-10-08。

采用前与目标项目的既有规范及业务契约核对。账户、支付、结算等是适用场景示例，不意味着目标项目必须具备这些中台。

适用范围：系统内各业务中台、业务应用、管理后台、对外接口和后台任务的 Java 服务。适用人员：开发、代码审查、测试及运维人员。

本规范由**通用开发基线、跨中台协作规则、业务专项要求**组成。支付是业务场景之一；用户与组织、账户、订单、结算对账等能力共同遵守通用基线，再按职责采用专项要求。新增中台沿用同一套方法明确边界，不复制整套支付模型。

日常实现与审查先按 [可执行规则](practical-rules.md) 定位适用条款，本文件按需提供完整依据。初始化另见开发 Skill 的初始化指南。

## 1. 规则分级与适用方式

### 1.1 依据与执行原则

基础编码以阿里巴巴《Java 开发手册（嵩山版）》为基线，参考 Google 编码与审查实践、AWS 可靠性实践、Microsoft API 与领域设计指南。各来源的采用范围及差异见第 20 节。

- **必须/禁止**：正确性、安全、兼容性与团队统一性要求。
- **建议**：默认采用；替代方案需说明适用条件，满足同等约束。
- **参考**：用于比较设计方案，不单凭未采用形成阻断。
- **待确认**：缺少业务依据或兼容证据，不得自行推定并投入使用。

规则强度与问题优先级分开：必须、建议、参考表示项目采纳的约束，P0～P3 按可证实的影响确定；待确认是证据状态。上游标为“强制”不代表项目已采纳，也不直接等于 P0/P1；推荐做法缺失只有在另有正确性或安全证据时才形成相应缺陷。

法律及机构协议、安全边界、已确认的业务不变量必须满足。团队编码以本规范和已批准的专项约定为准；外部指南不直接覆盖既有接口契约。冲突由业务或技术负责人确认，记录决策。

本稿经团队评审生效后，新代码及变更涉及的代码执行相应规则；存量问题按风险整改，不以规范升级为由扩大无关重构。

### 1.2 按能力选择规则

| 开发场景 | 必须采用 | 按实际需要采用 |
| --- | --- | --- |
| 所有 Java 服务 | 命名、分层、校验、授权、异常、日志、SQL、质量与发布基线 | 无需因“中台”名称引入全部中间件 |
| 普通查询、字典与配置管理 | 数据范围、稳定分页、版本冲突检查、必要审计 | 简单 Service + Mapper 即可，不强制聚合、状态机或 Outbox |
| 创建、审批、库存占用等有副作用操作 | 明确重复请求、并发和失败语义 | 按重复风险选择业务唯一键、幂等号、条件更新或资源预占 |
| 跨中台协作、可靠事件交付 | 契约与所有权、超时、一致性窗口、失败责任及恢复 | 仅可靠交付需要时采用 Outbox/Inbox 或等效机制 |
| 账户、支付、结算及金额操作 | 精确计量、资金不变量、持久化幂等、审计和恢复 | 采用对应专项规则，不混用不同中心的事实 |
| 导入、导出、批处理与报表 | 权限、限量、进度、失败明细及可恢复处理 | 超过同步容量或时限时采用异步任务 |

### 1.3 需求与验收对应

新增或改变业务行为按 REQ-001 确认输入、主体范围、正常/边界/失败及恢复语义，并对应需求、修改点与验收证据。小需求可在回复中简短说明；复杂需求复用项目已有需求和任务文档，不固定创建 spec/plan/tasks。已有会话或契约已确认的内容直接引用，不重复征求批准。

缺少定义时区分歧义、缺口、冲突与可逆实施假设。金额、权限、状态仲裁和恢复政策不能由技术示例或行业默认补齐；需要确认的部分与已经授权的独立工作分开推进。需求质量检查确认“期望是否明确”，行为验证确认“实现是否满足”；两者不能互相替代。审查时缺少未采用的模板不构成代码缺陷。

要求梳理进度或参照已有工程继续开发时，按 [Java 项目实践第 7 节](java-project-practices.md#7-对照工程推进进度与逐点确认)核对技术目标、实际调用链和当轮验证，区分实现、验收、可独立继续、待确认与已确认暂缓。复杂确认项拆到单个字段/接口/状态/政策，写明编号、依据/缺口、所需答案与具体阻断；用户已要求先完成确定工作时不重复追问同项，不用一个缺口阻断全部授权工作。旧源码、SDK 或枚举只证明其实际行为，不代替正式政策/协议与真实联调。

## 2. 领域边界与事实归属

### 2.1 一个事实只有一个权威责任方

中台边界按业务能力、统一术语和不变量确定。先明确谁产生事实、谁可修改、谁只消费，再决定模块及部署边界；不按页面菜单或数据库表机械拆服务。相同实体在不同领域可有不同模型，通过稳定标识和契约关联。[Microsoft 领域分析指南](https://learn.microsoft.com/en-us/azure/architecture/microservices/model/domain-analysis)

以下为多中台职责划分示例。实际 owner 以目标项目已确认的领域模型为准，不表示这些服务已经存在，也不构成固定的串行调用顺序。

| 业务能力 | 权威职责 | 其他中心的使用方式 |
| --- | --- | --- |
| 用户、组织与权限 | 主体身份、组织关系、权限及合同版本等已确认主档 | 使用获授权接口、事件及版本化引用，不复制一套可写主档 |
| 订单与业务应用 | 订单、报价、履约、售后及退款批准等业务依据 | 校验来源、版本、适用范围和有效期，不从支付结果反推履约事实 |
| 资金账户 | 额度、内部权益、预占、账务分录、义务变化及账户操作终态 | 引用操作结果和分录，不共享写账模型 |
| 支付 | 现金收付执行、支付尝试、机构结果和额度执行引用 | 消费执行事实，不将支付成功当作履约完成或银行到账 |
| 结算对账 | 分配计划、账期核对、差异闭环、商户账单及核验结论 | 使用版本化计划和结果，不反向覆盖支付或账户原始事实 |
| 门户、BFF 与报表 | 接口聚合、只读展示或派生分析 | 标明来源、时间及一致性延迟，不成为另一套业务事实写入点 |

计费、风控、付款等能力由目标项目明确职责归属；通用规范不新增中心，也不代替业务归属决策。

### 2.2 跨中台依赖

- 各业务数据由所属中心负责写入。禁止跨中心直接写表、共享 Entity，或通过依赖对方实现模块绕过契约。
- 跨中心读取优先使用公开查询接口或授权的只读投影；分析数据可通过受控同步进入独立分析存储，不默认跨生产业务库 Join。
- 同进程调用使用明确的模块接口，不为逻辑边界强行增加 RPC。拆分部署时评估独立发布、故障隔离、容量和运维成本。
- 多个模块需要相同概念时，先判断语义是否一致；禁止抽取一个包含所有中心状态和字段的“通用业务实体”。
- 上游模型经转换进入下游，机构 SDK、ORM 对象和历史系统状态不得直接污染本中心模型。
- 不同聚合引用稳定 ID；需要重现当时决策时保存来源、版本和必要快照，不仅保存可变主档的当前值。

### 2.3 每条协作链路的交付内容

跨中台用例必须说明：调用方与责任方、业务标识、身份范围、输入输出、幂等范围、超时与重试、版本兼容、一致性窗口、失败恢复和验收场景。

- 区分命令“请求执行”、事件“事实已发生”和查询“读取视图”；消息投递成功不等于业务执行完成。
- 明确流程负责人和每一步的状态责任方。跨中心失败时查询原操作，按已批准语义补偿，不用一个通用回滚动作撤销所有业务。
- 需要展示跨中心组合结果时，说明哪些字段已确认、哪些仍处理中；禁止用空值或零值掩盖依赖失败。
- 消费方可据事件建立投影，但权威状态冲突由事实所属中心处理；投影重建不能再次触发业务副作用。

## 3. 工程组织与职责分层

### 3.1 最小实现原则

写代码前依次判断：是否需要新增 → 是否已有实现 → JDK/Spring/现有 ORM 能否解决 → 已有依赖能否解决 → 是否配置即可 → 是否只需局部修改。

- 读取入口、调用方和数据变化路径后再修改；公共问题查清所有受影响调用方。
- 不为普通服务强制新增只有一个实现的接口，不为每张表配齐 Repository、Factory、Manager。
- 对复杂不变量使用有业务行为的领域模型；普通 CRUD 可直接使用应用服务与 Mapper。
- 不为一次性需求建立通用框架，不新增投机扩展点、重复工具类和无依据的中间件依赖。
- 使用已批准的 JDK、Spring 和依赖基线；版本、许可和升级影响统一管理，不在此冻结未经验证的组合。

### 3.2 层次职责

| 位置 | 职责 | 禁止 |
| --- | --- | --- |
| Controller | Query 校验、调用应用用例、Query/DTO/VO 转换 | 金额计算、审批判断、Mapper 访问和直接状态修改 |
| RPC Provider | 契约校验、建立可信上下文、调用用例 | 将内网访问等同于授权，重复实现业务 |
| Application Service | 业务权限、用例编排、事务边界及协调 | 大范围长事务，把第三方状态直接作为本地终态 |
| Domain（按需） | 聚合行为、业务不变量、领域服务和所需端口 | 依赖 Servlet、ORM、RPC、Redis、机构 SDK |
| Repository/Mapper | 数据查询、聚合保存及条件更新 | 决定业务审批、收费政策或跨中心流程 |
| Infrastructure Adapter | 存储、第三方协议及技术异常转换 | 吞掉不确定结果，向契约泄漏 SDK 对象 |
| Worker/消息入口 | 领取任务、校验来源、调用用例、记录处理结果 | 绕过业务校验另建一套执行逻辑 |

工程可按业务包组织、包内分层，也可在已有层内按业务子包归属；保留项目已采用的形态，不为目录统一全量搬动。领域层不依赖基础设施层；基础设施实现所需端口，装配在服务启动边界完成。简单业务不要求为了目录齐全创建空层。

### 3.3 模块与公共能力

- 契约模块仅包含对外接口、DTO、必要枚举及最小依赖，不携带持久化实现或业务启动配置。
- Web、服务与契约可按既有工程基线组织；是否拆为多个运行进程另行决策，不按一个聚合一个服务机械拆分。
- 公共库限定为稳定技术能力，例如统一响应结构、追踪上下文、错误抽象；业务规则和审批逻辑留在所属领域。
- Starter 只封装已有且多处复用的技术接入，条件装配可控，不隐式开启线程、消费消息或访问外部服务。
- 禁止循环依赖；公共库升级给出兼容范围，不能要求所有中台同一时间发布才能恢复正常。
- 中心间契约复用 DTO 不代表共享数据库实体；禁止将 ORM、机构 SDK 和 Web 框架作为基础契约的无关传递依赖。

### 3.4 开源架构实践的团队落地

模块边界与扩展点分别按 ARCH-001、EXT-001 执行；职责、反例、门禁及源码依据见 [Java 项目实践](java-project-practices.md)。公开契约不能暴露另一模块的 Mapper/DO，扩展回退必须有业务依据；已有分支和单模块足够时保持现状。采用 COLA 分层不意味着必须引入组件、多个 Maven 模块或 CmdExe 类；保持 Query/VO、雪花 ID 和既有 ORM 约定。

### 3.5 包与资源移动的同步验收

用户要求目录归类时按 ARCH-001 及 [Java 项目实践第 8 节](java-project-practices.md#8-按业务归属整理包与资源)形成移动清单，保持实际业务/分层职责；不为归类拆用例或建空模块。同步 Java 引用及字符串类名、组件/异常处理范围、Mapper 扫描、XML namespace/resultType 与递归资源加载、测试/检查脚本和源码导航；只在跨包调用确有需要时放开最小可见性。

干净构建检查旧 class/资源残留，实际装配核对所有预期 Mapper/语句与 Bean，递归检查不能以零文件为通过。对移动前后字段、业务正文和 SQL 做差异核对，再验证受影响行为。包名变化按 SERIAL-001 核验实际对象流、类型元数据和公开契约，UID 不变不等于旧数据兼容；目录移动不自动授权改变 HTTP、金额、状态、事务或 SQL。

### 3.6 Maven 依赖与制品验收

- 依赖坐标和版本来自已确认技术基线；沿现有 parent/BOM 管理兼容版本，不为一个工具方法新增依赖。`dependencyManagement` 只管理版本等信息，不自动引入依赖；`pluginManagement` 不等于插件已经参与生命周期。
- 正式发布使用可追溯、固定的制品；默认不依赖 SNAPSHOT、动态版本范围或被覆盖的同版本 RELEASE。已有内部发布流程的例外须有来源、锁定方式和恢复依据，不能仅凭命名断言制品稳定。
- 区分 compile、runtime、provided、test 和 optional 的实际传播与打包效果；测试依赖不进入正式运行包，provided 依赖由运行环境真实提供。不能靠本机 IDE 或本地仓库的偶然状态证明可部署。
- 发生依赖冲突时查看目标模块的 `mvn dependency:tree` 与 `mvn help:effective-pom`，核对实际选中版本、排除项和生命周期绑定，再用项目已有打包命令检查产物及最小启动。没有插件执行记录不称静态检查通过；多模块和插件有不同命令时以实际 POM 为准。

依据：[Maven 依赖机制](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html)、[POM 插件管理](https://maven.apache.org/pom.html)。版本升级不是规范安装的副作用。

### 3.7 技术栈组合与生成结果一致

初始化、调整技术栈或维护工程模板时，按 INIT-001 在已有工程基线中记录本次涉及的组合；普通业务修改不要求维护一张全技术目录。版本兼容、生成器支持范围和业务已确认选择分别记录，不能把某脚手架未实现的组合当成框架本身不支持。

| 组合项 | 要确认的依据与产物 |
| --- | --- |
| JDK / Spring / 构建工具 | 精确版本、parent/BOM、插件和包装器；实际依赖与编译/打包命令 |
| ORM / 驱动 / 数据库 / 迁移 | 实际版本与方言、迁移责任方及执行方式；依赖、配置、映射与迁移文件一致 |
| 认证 / Web / 浏览器 | 身份来源、过滤链、会话或令牌、适用 CSRF/CORS；实际业务入口和客户端配置 |
| 契约 / 注解处理 / 代码生成 | 已采用工具的版本、输入、输出位置及构建阶段；生成结果参与真实编译 |

只有实际存在多个入口（如 CLI、网页或智能体工具）时，复用同一份组合判定和稳定标识，检查各入口及持久化配置的往返一致性，不新增独立规则副本。发现冲突时说明不兼容项、依据和最小调整方向；不静默删除认证、校验、迁移等已确认能力，不自动升级到上游主分支版本。生成目录或依赖存在不等于能力已装配。

**验收**：针对本次受影响约束保留一个已允许组合和一个拒绝/冲突组合；前者在干净副本中生成、构建并核验实际装配，后者在写入前明确拒绝或交付待确认方案。比对已确认选择、保存配置、生成文件和有效依赖；未选能力不产生无用文件/依赖，已选能力不能只留下空壳。只做选型方案时不要求生成工程；不为验收安装未采用的脚手架或依赖。

### 3.8 工程模板的基线、更新与恢复

仅适用于脚手架或批量模板更新会覆盖已有工程文件的场景；普通手工编码不维护生成清单。只在可清理构建目录生成、不触及手写文件的接口代码按 6.7 验收，无需额外维护生成基线。沿已有工具记录生成器/模板版本、固定来源提交或制品哈希、输入配置、受管路径及首次落盘后的文件哈希；格式化后的实际文件才是基线。哈希用于比较，不记录密钥正文，也不从外部清单任意扩展写入范围。

更新前输出受影响路径、拟写内容、依赖变化及恢复范围，比较“初始基线 / 当前文件 / 新模板”。未改文件可按已授权范围更新；只有已验证的结构合并才保留双方不同位置的修改，同字段冲突停止该项。手工删除/重命名按本地修改处理，不自动复建旧路径、删除旧文件或接管新路径；缺少可信基线时列明差异，逐项审查后按已授权范围处理，不反填哈希伪造生成来源。确认过的计划在配置、模板或文件变化后失效，写入前重新比较；无需为此强制新建令牌协议。

保存本次拟修改内容的前像和必要操作记录，拒绝路径逃逸、符号链接或目录联接。失败时仅恢复本次写入且仍符合本次输出的文件；遇他人后续编辑保留并报告。中断后能识别未完成操作及恢复入口，状态记录在内容校验成功后推进。多文件写入不当然具备原子性，文件恢复也不恢复已执行的数据库迁移、安装脚本或外部副作用，后者另按授权和专项方案处理。

**验收**：在隔离副本覆盖未修改、本地修改、双方冲突、本地删除/重命名、无基线、计划后再编辑以及写入失败/中断；断言保留路径不被覆盖、恢复内容与前像一致、并发编辑不被回滚、重复执行不重复追加。发布跨版本升级能力时，用实际分发版本验证来源、目标构建与恢复，不把同版重生成当历史版本兼容。规范安装继续遵循本包安装说明的固定路径、区块和哈希保护，安装不触发工程更新。

## 4. 命名、格式与注释

### 4.1 命名与术语

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 包 | 全小写，按业务职责组织 | organization.application |
| 类/接口 | UpperCamelCase，表达业务职责 | OrganizationApplicationService |
| 方法/变量 | lowerCamelCase，动词体现行为 | approveApplication、reserveInventory |
| 常量/枚举值 | UPPER_SNAKE_CASE | MAX_PAGE_SIZE、APPROVED |
| Web 请求 | XxxQuery，含新增、修改和查询，放 query 包 | OrganizationUpdateQuery |
| Web 响应 | XxxVO，放 vo 包 | OrganizationDetailVO |
| 内部传输 | XxxDTO | OrganizationUpdateDTO |
| 持久化对象 | XxxDO，限持久层使用 | OrganizationDO |
| 转换类 | 统一 Converter 后缀 | OrganizationWebConverter |

禁止 data1、flag2、commonHandle、巨型 CommonUtils 等模糊命名。状态字段不得只用 boolean 表达包含多种中间态的业务过程。

账号、主体、企业、组织、应用、商户等概念各自定义，不因显示名称相似混用 ID。企业 Enterprise 与租户 Tenant 是否一致由目标项目定义；禁止未经确认互相替换，多个身份范围并存时明确映射。

### 4.2 格式

- UTF-8、LF、文件末尾换行；Java 使用 4 个空格，禁止 Tab，续行额外 4 个空格。
- 单行默认不超过 120 字符；长 URL、import 等例外由统一检查规则控制。
- if/else/循环必须有花括号；优先清晰的前置校验，避免深层嵌套。
- 禁止通配符 import，删除无用 import；格式整理不夹带无关功能修改。
- 使用构造器注入；依赖字段优先 final。单例服务不保存请求级可变状态。
- Query、DTO、VO 统一使用普通 class + Lombok，不默认采用 record；访问器采用 getXxx/setXxx，不启用 fluent 风格。
- 请求 Query 使用 @Getter/@Setter 和无参构造，字段默认值与 null/空值策略显式定义；必要时手写 setter 做默认值归一化，合法性仍由 @Valid 校验。
- 只读 DTO/VO 使用 @Getter、final 字段与构造方法；无额外逻辑时可用 @AllArgsConstructor，需要参数校验或集合防御性复制时保留显式构造方法。需要反序列化的内部 DTO 按真实协议提供可绑定 JavaBean 或显式 creator/property 映射，不能为绑定强行破坏只读状态或绕过构造校验。
- 不统一套用 @Data：避免无意生成敏感字段 toString、可变 equals/hashCode 或越权 setter；领域聚合不开放任意状态修改。只有确需值比较时才生成并检查 equals/hashCode，不能假设 class 自动拥有 record 的值语义。

Google 默认使用 2 空格、100 字符；团队保留阿里手册的 4 空格、120 字符，同时借鉴命名、导入和花括号等规则。IDE 与构建不得混用相互冲突的格式化配置。[Google Java Style](https://google.github.io/styleguide/javaguide.html)

### 4.3 注释

- 新增或修改的类和字段必须有准确业务注释，Query、DTO、VO 尤其要说明传输契约；不为补注释批量改动无关历史代码。
- 状态注明可选值，金额和数量注明单位，展示字段注明来源及映射，时间注明时区。
- 可空字段说明 null 语义，不默认解释为零、失败或“不限制”。
- 手写方法和构造方法使用 Javadoc；按实际签名补 @param、@return，主要业务拒绝或校验异常补 @throws。Service、Controller、Repository 不能只有类注释；私有权限、转换、默认值处理等方法也说明职责与边界。
- 方法说明写清业务目的、参数来源与前置条件、返回值及空结果语义；涉及权限、分页、状态、副作用或重试时说明相应约束。只读方法不虚构事务或补偿能力；异步操作说明查询及完成语义。
- Lombok 生成的访问器与构造方法不额外手写重复注释，语义写在字段和类上；覆盖方法可继承接口契约，但新增限制或副作用必须补充。禁止用“查询数据”“处理逻辑”等空话代替方法契约。
- Controller 注释覆盖 HTTP 方法、完整路径、绑定方式及主要错误；Service 注释覆盖业务前置条件、动作权限、资源范围、排序/分页和空结果；Repository 注释说明查询范围与结果语义，不把数据访问写成已经完成业务授权。
- @throws 只写本方法实际抛出或传播的异常；框架绑定、安全过滤链等错误写在接口契约中，不伪装为方法直接抛出。修改行为时同步注释，OpenAPI 注解不替代源码业务说明。
- 复杂注释说明业务原因，不复述 getter/setter；TODO 包含问题与处理条件，必要安全检查不能无限延期。

## 5. Java 基础与异常处理

- 使用 equals 比较包装对象的值，避免自动拆箱空指针；equals/hashCode 一致，Map key 的参与比较字段保持稳定。
- 金额、费率、额度等精确值禁止 float/double；BigDecimal 使用精确输入，数值比较用 compareTo，尺度另行校验。
- primitive 仅用于明确不可缺失的值；缺失状态、金额或 RPC 失败不能被默认 0 掩盖。
- 正常无数据返回空集合；查询失败必须表达错误，不能伪装成“没有记录”。
- Collectors.toMap 明确重复键处理，业务标识冲突不得默认后值覆盖；注意不可变集合、视图集合及迭代修改行为。
- 时间使用 java.time。事件时刻用 Instant 或明确偏移量；账期、自然日与截止时间按业务时区计算，不依赖服务器默认时区。
- I/O、连接和响应流由框架或 try-with-resources 管理；禁止静默丢弃关闭异常及资源泄漏。
- 业务拒绝、输入错误、权限拒绝、并发冲突、依赖不可用和程序缺陷分类处理，避免一律 RuntimeException。
- 捕获异常必须有明确处理目的；需要继续传播时保留 cause，禁止空 catch 或只记日志后返回成功。
- 不重复打印同一异常堆栈；在能补充业务上下文的责任边界记录，向外返回安全且稳定的错误语义。
- Spring 已提供的数据访问异常转换优先复用，不机械包装无意义的 DAOException；工具方法优先 JDK 和已有依赖。

### 5.1 值、对象和常量

- 包装类型和 String 的值比较用符合 null 语义的 equals/Objects.equals；不能依赖 Integer 缓存或字符串驻留产生的 `==` 结果。可空 Boolean 的 true 判断可用 `Boolean.TRUE.equals(value)`；null 是否等于 false 由业务决定，不能借工具调用悄悄抹去“未提供”。
- 金额、比例和精确计量从十进制字符串、整数最小单位或精确数据源构造 BigDecimal，不直接用 `new BigDecimal(double)`。明确单位、精度、舍入时点和 RoundingMode；无终止小数的除法明确 scale/rounding。数值相等用 compareTo，equals 同时比较 scale；BigDecimal 作 Map/Set 键时先确认等价政策。
- 重写 equals 同步满足 hashCode 契约；Set/Map 的参与相等性字段在存放期间保持稳定。跨继承层的相等性需保持对称、传递和一致；不自动生成覆盖敏感字段的 toString，也不把所有字段机械纳入相等性。
- 覆盖方法加 @Override；不通过实例访问静态成员。Boolean/boolean 字段默认命名 `enabled` 等业务词，标准访问器由类型/框架生成；可空 Boolean 不人为混用 `isEnabled()` 与 `getEnabled()`，用真实 Jackson/Bean 映射验证属性名。已发布字段保留兼容策略，不批量改名。
- 构造/工厂完成必要不变量，setter 不承担隐蔽远程调用或持久化；静态可变状态、单例 Bean 的请求字段须有线程安全依据。final 引用与不可修改集合不代表其中对象不可变；浅拷贝不能隔离可变嵌套对象。
- 状态、单位和重复使用的业务常量用现有枚举/局部常量表达，不建万能 Constants 类；枚举对外使用稳定已确认值，不持久化 ordinal。字符串拼接仅在有实际循环/性能依据时复用 StringBuilder，不机械替换普通可读表达式。
- 删除/废弃公开成员先核对调用方与协议兼容；@Deprecated 不等于允许立即删除。不要为“基础规范齐全”新建对象拷贝框架或重复工具类。

### 5.2 日期、时间与区间

- 区分业务日期 LocalDate、带时区的时间点 Instant/OffsetDateTime 和不含偏移的 LocalDateTime；后者不能独立表示全球唯一时间点。格式、时区、精度、边界包含关系在接口与存储契约一致，服务器默认时区不作为隐含业务规则。
- `Y` 是周所属年，`y` 是纪年年，`u` 是公历年份；业务日期不能误用 `YYYY`。`M/m` 分别为月/分钟，`H/h` 分别为 24/12 小时。公历严格解析可用 `DateTimeFormatter.ofPattern("uuuu-MM-dd").withResolverStyle(ResolverStyle.STRICT)`；现有 yyyy/纪年格式先按实际语义核验，不全量替换。
- DateTimeFormatter 可共享；SimpleDateFormat 等可变格式器不跨线程无保护共用。旧 JDBC/第三方时间类型仅在适配边界转换，不因业务层推荐 java.time 就删除必要适配。
- 日历年/月/日计算用日期 API；`plusYears(1)` 与固定 365 天、当地一天与固定 24 小时不必等价。时长用 Duration，日期间隔用 Period/日期运算；夏令时重叠/不存在的本地时间按项目政策处理。
- 时效规则复用已存在的时钟注入方式或 Clock，验收固定时间与时区；不靠 Thread.sleep 等待到期，不为一个纯格式化方法新增时钟框架。

依据：[JDK 21 日期格式](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/time/format/DateTimeFormatter.html)。

### 5.3 集合、数组与排序

- `Arrays.asList` 是数组支持的固定大小视图：set 会影响原数组，add/remove 不受支持；传入 `int[]` 得到的是包含该数组的单元素列表。需要独立可变副本时明确 `new ArrayList<>(...)`，基本类型数组按实际元素转换。
- `subList` 是视图，修改和原列表关联；通过视图以外的路径结构性修改原列表后，不能继续依赖该视图。跨生命周期传递前按用途复制。无参 toArray 返回 Object[]，不能强转 String[]；按目标类型用 `toArray(String[]::new)` 等受支持 API。
- foreach 中不直接结构性修改普通集合；用迭代器的 remove、removeIf 或新结果集并保持原业务语义。并发集合的迭代/计算保证按具体 API 核验，不把 fail-fast 当并发保护，也不把“线程安全集合”当多步业务原子操作。
- toMap 遇重复键明确拒绝、归并或选择规则；核验 value 为 null 的处理，不能用合并函数掩盖非法输入。顺序有业务含义时明确集合/收集器顺序；parallelStream 的共享状态、线程上下文和阻塞操作需独立证据，默认不靠并行加速猜测。
- Comparator 用 Integer.compare/Long.compare、comparing/thenComparing 等实现，不用相减返回值导致溢出。满足反对称、传递与相等项比较的一致性；null 和并列次序显式定义。TreeMap/TreeSet 比较为 0 会视为同一键/元素，不能误丢同分对象。
- List.of/copyOf、Stream.toList、Collectors.toList 的 null/顺序/可变性区别按 15.1 核验；不可修改结构与深度不可变分开，禁止只凭名字或同一成功用例判定等价。

依据：[JDK List](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/List.html)、[Comparator](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Comparator.html)。

### 5.4 分支、异常与资源

- 可空值先处理再拆箱；三元表达式混合包装/基本类型可能隐式拆箱。枚举/字符串 switch 明确 null、未知值和 default 行为；传统 switch 的贯穿必须有意且清楚表达，不将未知状态回退为业务成功。
- finally 不 return/throw 来覆盖正常返回或原异常；资源优先 try-with-resources，必要时保留 suppressed 异常证据。清理动作不掩盖原失败，锁/线程上下文释放见 8.2。
- 按能处理的范围捕获异常，保留 cause；校验失败与基础设施故障不合并成默认成功、空列表或 false。任务/框架边界需要捕获时明确报告与恢复责任，不机械全局 catch Throwable，也不禁用合理的边界异常处理。

### 5.5 Java 基础的最小验收矩阵

只选本次行为对应行；断言结果/副作用，不把“未抛异常”当验收。可执行入口见 JAVA-001。

| 场景 | 输入或执行条件 | 必须断言 |
| --- | --- | --- |
| 包装值/空值 | 两个同值但不同引用的包装对象；可空 Boolean；三元分支取 null | 值比较正确；缺失政策不变；无意外拆箱 NPE |
| 精确数值 | 0.1 + 0.2；1.0 与 1.00；1 / 3；舍入边界 | 十进制精确结果、数值/scale 契约、既定舍入与单位 |
| 日期 | 2019-12-30；2024-02-29；2023-02-29；明确时区边界 | 不输出错误周所属年；合法闰日通过、非法日期拒绝；同一时间点一致 |

## 6. Web、RPC 与接口契约

### 6.1 对象边界

Web Query → Controller/Converter → 内部 DTO → 应用用例 → 所需领域模型与持久化对象。响应沿内部 DTO → Web VO 转换。

- Controller 仅接收 Query、返回 VO 或统一响应包裹的 VO；禁止直接使用 DTO、BO、DO、Entity 或 ORM 分页对象作 Web 出入参。
- 请求统一 Query 后缀，新增和修改也如此；内部用例对象可按约定采用 Command，不作为 Web 请求类型。
- 分页使用分页 Query 和分页 VO，内部分页 DTO 不直接暴露。
- 转换使用明确字段映射；禁止把 Query 自动复制到 DO 后整行更新，禁止客户端覆盖认证上下文。
- Web 与 RPC 均校验契约；网关校验不免除应用服务的资源归属及业务权限检查。
- 枚举合法性、长度、集合大小、数值边界在入口校验；跨记录不变量在用例或领域层校验。

下面仅展示组织领域请求的命名、边界和注释，不定义正式 API：

```java
package com.company.platform.organization.web.query;

import java.io.Serial;
import java.io.Serializable;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.PositiveOrZero;
import jakarta.validation.constraints.Size;
import lombok.Getter;
import lombok.Setter;

/** 修改有权管理的组织展示名称；不修改法定主体身份。 */
@Getter
@Setter
public class OrganizationUpdateQuery implements Serializable {
    /** Java 对象序列化版本，兼容演进时保持稳定。 */
    @Serial
    private static final long serialVersionUID = 1L;

    /** 目标组织标识；应用服务校验其所属企业及操作者管理权限。 */
    @NotBlank
    private String organizationId;

    /** 组织展示名称，长度为 1～100 个字符。 */
    @NotBlank
    @Size(max = 100)
    private String displayName;

    /** 最近一次读取的版本号；用于拒绝覆盖并发修改，不作为权限依据。 */
    @NotNull
    @PositiveOrZero
    private Long expectedVersion;
}
```

expectedVersion 必须落实到条件更新并检查影响行数；仅声明字段不能防止覆盖。主体身份、金额等字段是否可由客户端传入，由其业务契约确定，不能把支付报价规则套到所有管理接口。

### 6.2 HTTP 方法与返回契约

- 业务请求参数超过 3 个时，统一使用 POST 和 `@Valid @RequestBody XxxQuery` 接收 JSON；3 个及以内的简单只读查询可使用 GET 和 `@Valid @ModelAttribute XxxQuery`。这是团队接口设计约定，不是 HTTP 协议规定的参数上限；3 个及以内不意味着禁止 POST。
- 参数按接口契约中客户端可提供的业务字段统计，包含必填、可选、分页、排序和路径业务参数，不按某次请求实际填了几个字段计数。Query 包装不算一个参数；继承字段同样计入。Authorization、CSRF、追踪头及框架注入的 Authentication 不计入业务参数，业务字段不能改放请求头来规避计数。
- 嵌套对象按可输入的叶子业务字段统计；集合按一个集合字段计数，不按元素数量计数。复杂嵌套、批量集合或长文本即使不超过 3 个字段，也优先使用 POST JSON，并明确大小上限；不能仅凭字段少就使用 GET。
- 分页按同一规则判断：`pageNo + pageSize` 为 2 个，增加 `name` 为 3 个，简单只读查询可用 GET；再增加 `status` 为 4 个，使用 POST。以已经定义的筛选条件计数，不为可能出现的未来字段提前强制 POST。
- GET 不触发业务状态变化，不依赖 JSON 请求体；POST 查询也保持业务只读。认证主体来自框架安全上下文，不放进 Query 作为客户端可修改属性。创建、修改、删除等操作仍按业务语义和既有契约选择方法，不能因参数少而改用 GET。
- POST 查询明确空对象、字段缺失/null、缺失/非法请求体、默认值与校验语义；错误媒体类型返回 415，JSON 解析或约束失败返回 400。嵌套对象和集合同步限制规模并落实级联校验；分页验收见 WEB-002。不得依赖通用客户端按 GET 的缓存/重试语义处理 POST。
- 从 GET 改 POST 时同步调用方、接口文档、验证和安全配置；已有公开契约先评估兼容性。采用 Cookie 或 HTTP Basic 等浏览器会自动附带的凭证时保留适用的 CSRF 保护，不能只为让 POST 调通而全局关闭。
- POST 不自动保护敏感信息；URL、请求体和日志均按实际字段做访问控制与脱敏。创建、修改及其他有副作用操作按业务语义和既有契约选择方法。
- Controller 的 Javadoc 写清方法与完整路径、参数来源、默认值、权限、返回及主要错误；关键绑定/转换处解释边界原因。Javadoc 是源码说明，OpenAPI 接口文档注解按项目已采用的工具补充，不为注释单独引入整套依赖。

依据：[HTTP GET 语义](https://www.rfc-editor.org/rfc/rfc9110.html#name-get)、[Spring 6.2 ModelAttribute](https://docs.spring.io/spring-framework/reference/6.2/web/webmvc/mvc-controller/ann-methods/modelattrib-method-args.html)。

返回与兼容要求：

- 使用统一响应、错误码及分页结构。业务拒绝、未受理、已受理未完成、完成和依赖异常分开表达。
- HTTP 状态与响应语义一致，不能全部返回 HTTP 200 + false；统一覆盖绑定、媒体类型、路由及安全过滤链错误，按 ERR-001 和 AUTH-001 验证执行顺序与 CSRF。机构回调按对方 ACK 协议处理，不强行套普通 VO 外壳。
- 错误码稳定；客户端不解析提示文案作判断。返回安全业务原因和关联标识，隐藏堆栈、凭据及无权查看的内部信息。
- 异步操作给稳定操作号、状态查询和终态语义；HTTP 202 不代表完成。建议重试间隔遵守已定义协议及等待预算。
- 超过 JavaScript 安全整数范围的 ID、精确数值采用契约约定的无损表示，如十进制字符串。
- 分页建议默认 20，最大值统一限制；排序字段白名单并补充唯一键，连续遍历说明游标或快照语义。
- 明确字段缺失、null、空字符串及默认值的区别；部分更新不能将“未提供”解释为“清空”。
- 删除字段、改变类型、单位、枚举语义、错误码或幂等行为须版本化评估；新增枚举同样检查旧消费者。
- 新字段的默认行为必须兼容，写接口中影响权限或业务意图的未知字段不得静默接受。
- 接口文档包含身份范围、字段含义、超时、幂等及失败恢复。废弃接口给出迁移窗口、调用方清单和下线条件。

上述稳定错误、分页和异步操作原则参考 Microsoft 指南，保留团队契约，不照搬 Azure 专属请求头和版本参数。[Microsoft API Guidelines](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md)

### 6.3 序列化契约

Query、DTO、VO 采用普通 class + Lombok，同时实现 Serializable；每个类和可序列化子类显式声明自己的 serialVersionUID，当前 Java 21 基线加 @Serial。具体正反例、对象图、泛型、UID 演进和验收遵循 [SERIAL-001](practical-rules.md#serial-001序列化能力和线上的协议分别验证)。已有共享请求基类可复用，但不将 Web Query 和内部 DTO 合并成一个继承体系。

HTTP JSON、Java 对象流和具体 RPC/缓存/消息序列化器分别记录。JSON 不依赖 Serializable；不能将“加了接口”或“原生往返通过”报告为实际跨服务协议验证完成。UID 控制 Java 对象流类版本，不代替接口版本；新旧版本读取与数据迁移单独评估。

Jackson 输入对象用可绑定属性或明确的 creator；只读输出对象保留不可变性。序列化元数据不出现在业务 JSON，类型恢复、字段脱敏、日期/金额精度及未知字段策略按真实配置验证。原生反序列化不应接收不可信输入，也不能依赖普通构造方法执行校验。

依据：[JDK Serializable](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/Serializable.html)、[@Serial](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/io/Serial.html)、[Jackson 注解说明](https://github.com/FasterXML/jackson-annotations/wiki/Jackson-Annotations)。

### 6.4 前后端 JSON 与字段契约

新增浏览器 JSON 接口默认沿现有 REST 风格，以业务资源和语义确定路径/HTTP 方法；方法选择遵循 6.2，不因套用 REST 教条改已发布接口。下载、文件上传、流式响应及外部回调按实际媒体类型/协议返回，不强行套 JSON 包装。

| 契约项 | 新接口默认与必须明确的内容 |
| --- | --- |
| 编码和媒体类型 | 网络 JSON 使用 UTF-8；返回正确的 application/json，不伪装成 text/html，不允许 NaN/Infinity；上传/下载另约定媒体类型。收到不支持的类型按错误契约拒绝 |
| 字段名和类型 | JSON 业务字段默认 lowerCamelCase，布尔用稳定业务属性名；同一字段在成功/失败/不同状态不在字符串、数字、对象之间变化。旧 snake_case 等契约明确映射并保留兼容 |
| 空值与集合 | 正常无列表项返回 []，非 null 或拼接字符串；对象不存在、字段未提供/null/空字符串、部分更新清空分别定义。查询失败不包装成空结果；泛型包装的 data 具体类型写清 |
| ID 与精确数值 | 雪花 ID 等可能超出 JS 安全整数范围的标识使用字符串，前端不得 Number()/parseInt 后再传回。金额/高精度数值说明单位、scale 和舍入，采用既定字符串或安全的最小单位整数；禁止先经 double 再序列化 |
| 日期/时间 | 日期用明确格式如 yyyy-MM-dd；唯一时间点新契约默认采用带 Z/偏移的 ISO 8601 字符串，说明精度与展示时区。若已采用时间戳须标明秒/毫秒及范围；不猜 10/13 位单位或浏览器本地时区 |
| 枚举/状态 | 公开稳定枚举值及含义；前端展示文案与机器状态分开，不以中文 message 判定状态；新增未知值的显示/禁止操作策略与旧消费者兼容 |
| 业务校验 | 长度、格式、数值范围、集合大小、字段组合和嵌套对象在后端真实入口校验；前端校验辅助交互。企业、用户、金额归属及角色不从可修改请求字段获得信任 |
| 文档/联调 | 沿项目已有 OpenAPI/接口文档记录字段、样例、单位、默认/缺失政策、权限、错误、分页、幂等、兼容窗口；核对实际 JSON 和生成客户端，不为一份文档自动新增工具依赖 |

前端按真实 HTTP 状态、响应媒体类型及稳定错误码处理结果；401 的登录/刷新策略有界，403 不循环重登，网络超时和 5xx 不自动重发有副作用请求。用户可展示的安全 message 可用作提示；字段错误应能定位到既定字段名，响应/请求关联标识可用于排查但不携带敏感内容。先复用现有拦截器/错误包装，未确认的新外部协议不机械添加 code/message/data。

依据：[JSON 标准 RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html)、[HTTP 语义 RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)；对象边界、序列化与稳定错误沿 WEB-001、SERIAL-001、ERR-001。

### 6.5 HTTP 状态、传输、缓存与跳转

| 情况 | 新接口默认行为及兼容边界 |
| --- | --- |
| 正常读取/完成 | 200 返回实际业务结果；创建资源可用 201 并给资源定位信息；204 无响应内容，前端不能再解析 JSON |
| 异步受理 | 202 只表示受理，返回已确认查询标识/路径；前端区分受理与最终成功，轮询有停止条件与退避 |
| 绑定/校验、媒体类型、大小 | 无效 JSON/常规参数错误默认 400；不支持的媒体类型 415；超过实际请求上限 413。项目采用 422 等合法契约时保持一致，不擅改已有错误码 |
| 身份/权限/资源 | 401 未认证并按认证方案处理；403 无权；404 不存在。为防资源枚举统一 404 时按已有政策执行；不能只在 Controller 内处理而漏掉过滤链错误 |
| 并发/重复/频控 | 状态或同幂等键异参冲突按契约如 409；请求过多按既定频控契约如 429，Retry-After 有真实等待依据才提供。同参重复沿 IDEM-001，不一律报错 |
| 未知故障 | 500 等 5xx 与故障类别相符，脱敏并有可定位证据；旧版 HTTP 200 + 业务错误的例外须明确给前端及迁移计划，不将它自动推广为新接口默认 |

- 浏览器/外部信任边界默认 HTTPS，禁止凭据和令牌放 URL；TLS 终止后的内部链路按已确认网络边界，可信代理头只从受控代理采信，不因一条规则自动改部署。CORS 白名单、cookie 与 CSRF 组合沿 AUTH-001，CORS 不替代认证和资源授权。
- 请求体字节数、文本/集合/嵌套深度、上传文件及返回规模按真实业务确定上限；网关/容器/解析器/业务入口协调，并核验分块请求、压缩请求（实际支持时）及异常包装。不能只信客户端 Content-Length，也不全局套一个示例阈值。列表沿 WEB-002；大导出沿异步/分批方案。
- 个体敏感响应默认禁止存储（如 Cache-Control: no-store），核验网关/CDN/浏览器实际行为；需要缓存的公开或私有数据明确缓存范围、期限与权限隔离。no-cache 允许存储但要求复验，不等于 no-store；ETag/304 仅在实际采用条件请求时验收，304 不带 JSON 响应体。
- 跳转只到受控相对路径或解析后校验的允许目标（协议、host、端口等按契约），不使用 contains/字符串前缀判断域名。拒绝未允许的协议相对 URL、userinfo 或危险 scheme；编码规范化与解析使用已有组件。HTTP 重定向的 303 与 307/308 方法保留语义不同，不能把含凭据的请求体或头转发到不受信目标。
- 文本按前端实际 HTML/属性/URL/脚本上下文安全输出，不把后端全局删除字符当 XSS 方案；富文本按允许内容净化，禁止将任意服务端 message/用户输入直接送进 innerHTML。上传类型/内容/文件名与下载响应头按已有文件专项校验。

依据：[OWASP REST 安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)、[XSS 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)、[跳转校验](https://cheatsheetseries.owasp.org/cheatsheets/Unvalidated_Redirects_and_Forwards_Cheat_Sheet.html)、[HTTP 缓存 RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html)。

### 6.6 前后端接口的具体验收

使用真实入口或相应 Web 测试层检查原始状态/头/JSON，再由实际浏览器或项目 JS 运行时读取；序列化单元测试不证明过滤链、网关与浏览器行为。适用规则 WEB-001/002/003、SERIAL-001、ERR-001、AUTH-001，既有参考工程并未自动覆盖本节全部场景。

| 场景 | 固定输入/执行条件 | 判定与证据 |
| --- | --- | --- |
| 方法/绑定 | 定义 3/4 个业务字段；缺失/null/空白/非法 JSON；错误 Content-Type | 遵循计数/兼容政策，真实绑定和校验；400/405/415 等错误与文档一致 |
| 字段精度 | ID 9007199254740993；金额 0.10；同字段各业务状态 | JSON 中精确值和类型稳定；JS 往返 ID 字符串不变；金额单位/scale 不丢 |
| 日期 | 带偏移时间点；日期；秒/毫秒时间戳（实际采用时） | 前后端表示同一时间点，展示时区明确；无单位误判、日期漂移或非法日期放行 |
| 空值/演进 | 无列表项、缺失字段、显式 null、未知字段/枚举、旧客户端读取新响应 | [] 与错误区分；清空与不改区分；兼容或拒绝政策有真实证据 |
| 权限/错误 | 未登录、已登录无权、跨企业、正常空结果、存储故障 | 动作/资源保护生效；稳定错误不泄漏堆栈/SQL；前端不无限刷新或将故障当空列表 |
| HTTP 特例 | 204、202、文件下载；条件请求 304（实际采用时） | 无内容不解析 JSON；202 不报最终成功；下载/流媒体不强套包装 |
| 请求大小 | 上限、上限 + 1；分块/压缩请求（实际支持时）、过大列表/上传 | 限制在真实路径生效，413 等契约一致；不先无界读入内存再拒绝 |
| 缓存/安全展示 | 敏感页经现有代理；用户文本含 HTML；未允许的跳转 URL | 缓存政策有响应头及设施证据；文本不执行脚本；跳转拒绝且凭据不外传 |
| 重复/失败恢复 | 双击提交、连接超时、异参重用幂等键、异步失败 | 有副作用不盲重试；重复结果/冲突/查询恢复符合业务状态，不能只靠按钮禁用 |

### 6.7 已采用接口代码生成时的契约验收

沿项目已有方式明确契约权威来源是接口描述还是服务代码，以及导出、生成器版本、输入、输出目录和实际构建命令；不同时维护两份可随意修改的权威定义，不为普通接口强制引入 OpenAPI/客户端生成器。生成代码和手写代码分清维护边界，不能靠手改输出掩盖源契约或模板错误；会覆盖已有工程文件时更新保护按 3.8。

服务端生成类型仍遵守 WEB-001、SERIAL-001 的 Query/DTO/VO 与序列化边界；必要映射留在现有边界，不直接暴露内部 DTO、Entity 或 ORM 分页。生成模型、默认方法和注解不证明路由、参数校验、权限或业务实现已经生效。约束、ID/金额类型、空值、时间、枚举、分页及错误响应与真实协议一致，公开契约变化先核验旧消费者。

**验收**：在干净副本按已定输入重新生成，确认构建阶段真实执行且前后端实际消费方能编译；若产物入库，核对生成差异，若在构建目录生成，核对产物参与编译/打包。选择一个受影响字段或错误场景，检查接口描述、生成客户端与真实 HTTP/JS 读写一致；出现陈旧客户端或类型不符时由现有检查拒绝，不仅比较源码字符串。浏览器安全链和真实外部联调仍单独留证据；只生成服务端接口不声称已完成前端客户端生成或联调。

## 7. 通用状态、幂等与并发修改

- 有业务生命周期的对象维护状态转换表：当前状态、事件、允许条件、目标状态、并发条件、重复行为和恢复责任。
- 审批、订单、库存、任务等状态在所属领域流转；禁止通用“改状态”接口绕过业务条件。
- 请求受理状态、业务执行状态和通知状态分别建模；查询投影更新不等于原业务重新执行。
- 对可能重放并产生重复副作用的操作，明确幂等范围、键、保留时间、同参重复返回和异参冲突。纯读取不为统一外观额外持久化幂等记录。
- 幂等号标识一次业务意图；内容相同的两次合法操作不一定重复。参数摘要只用于核对同一操作，不单独决定意图。
- 幂等记录与本地业务变更原子提交，并以唯一约束等持久化原子保护兜底；“先查再插”不是并发保证。
- 条件更新带原状态或版本并检查影响行数；失败区分版本冲突、重复操作、无权限和不存在。
- 幂等保留窗口覆盖迟到请求、消息和恢复；需要永久防重的事实不能因缓存过期重新执行。
- 一般配置可通过版本条件更新控制重复覆盖；支付、扣账、发放等不可重复副作用采用更严格的持久化幂等。
- 不确定结果单独表达，按原操作查询；只有权威证据证明未执行且契约允许，才进入规定重试或重建流程。

幂等设计参考 AWS 的调用方请求标识、重复语义和同号异参处理，并按各领域风险确定强度。[AWS 幂等 API 实践](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)

采用状态机组件时按 [状态与事件边界](java-project-practices.md#4-状态机与事件不替代持久化保护)区分规则路由、条件判断、持久化 CAS 和副作用恢复；事件转换存在或返回目标状态不证明数据库修改已成功。

## 8. 事务、锁与线程

- 本地事务覆盖必须原子变化的数据；需要可靠事件时，业务与 Outbox 同事务。普通 CRUD 不因本规范强制发布事件。
- @Transactional 放在可经代理调用的用例或持久化边界；核验自调用、捕获异常、rollbackFor 和实际事务管理器。[Spring 事务说明](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html)
- 不使用长事务包住慢 HTTP/RPC 并持有行锁；远程副作用与本地提交分阶段处理。数据库回滚不能撤销对方已经完成的操作。
- 跨中心不假设共享数据库事务；按业务选择同步校验、可靠事件或可恢复编排，不默认全系统引入分布式事务框架。
- 无依据不使用 REQUIRES_NEW。不得拆开必须原子提交的预算、明细和状态。
- 明确竞争对象、锁范围、锁顺序和死锁恢复；必要的重试重新读取状态，不能盲目重放远程副作用。
- 唯一键、条件更新、短事务是持久化保护；synchronized、volatile、内存 Map 或 Redis 锁不能单独保证多实例一致性。
- 分布式锁有所有者校验、租约和原子释放；实际写入边界以持久化条件/版本或经验证的 fencing 拒绝迟到操作。随机 owner token 不等同 fencing token，仅在应用前置检查租约不足以保护后续写入；Redis 细则见专项第 6 节。
- 执行器明确容量、队列、拒绝策略、超时及关闭行为，禁止无界堆积。
- 虚拟线程适合部分阻塞 I/O，不替代数据库连接和外部服务并发限额，不池化虚拟线程。[OpenJDK JEP 444](https://openjdk.org/jeps/444)
- 异步显式传递可信身份和追踪上下文并清理，禁止 ThreadLocal 串请求；跨线程不假设继承原数据库事务。

### 8.1 注解要经过实际代理入口

适用于本次新增或改变的事务、缓存、异步方法及其调用路径。先核验 Spring 版本、Bean 注册、功能启用和 advice 模式，再沿实际调用方确认是否经过代理；不把一份注解清单当成生效证明。

- proxy 模式下，同实例内部调用不触发被调用方法的新拦截。已有外层事务可能仍有效，不能将内层 REQUIRES_NEW 等传播未生效误报成整个用例没有事务；直接 new 或初始化回调也不能假定具备完整代理行为。
- Spring 6.0 起，默认类代理的 protected/包可见事务方法可被拦截；JDK 接口代理要求事务方法 public 且存在于代理接口。还需检查 publicMethodsOnly 等实际配置，不能一律报告“protected 的 @Transactional 失效”。类代理下 private/final 方法不可通过覆盖拦截；AspectJ 模式按已采用的织入配置另查。
- @Cacheable、@Async 在 proxy 模式下也检查自调用，但各自的可见性、启用配置及执行语义查对应文档，不能套用事务的可见性规则。修正优先调整现有职责与入口；程序式事务沿用项目设施，不为绕过一次自调用自动引入 AspectJ、自注入或新框架。
- 验收从真实调用方进入受管 Bean：事务核验活动状态、传播和失败后的数据结果；缓存核验同键重复调用的命中与失效；异步核验选定执行器、异常及完成语义。直接调用 new 出来的对象或 mock 目标只证明方法体；源码推导与实际执行分开报告。

依据：[Spring 6.2 事务](https://docs.spring.io/spring-framework/reference/6.2/data-access/transaction/declarative/annotations.html)、[代理机制](https://docs.spring.io/spring-framework/reference/6.2/core/aop/proxying.html)、[缓存](https://docs.spring.io/spring-framework/reference/6.2/integration/cache/annotations.html)、[异步](https://docs.spring.io/spring-framework/reference/6.2/integration/scheduling.html)。其他版本先核验对应行为，不要求升级到 6.2。

### 8.2 常用并发场景

- 复用受管执行器，线程名称能定位业务；平台线程池明确线程数、队列容量、拒绝策略与关闭责任。无界队列/newCachedThreadPool 等默认不作为无流量上界的请求执行器，不能只靠“最大线程数”声称有限流；虚拟线程按实际 JDK 能力使用，仍限制数据库连接、远端并发和在途任务，不机械禁止全部 Executors 工厂。
- Future/CompletableFuture 的等待超时不证明后台副作用已取消；核验实际任务/驱动是否响应取消、完成结果去向和关闭时的等待预算。异常任务有可定位记录；提交失败、队列拒绝和关闭阶段不能默认为已执行成功。
- 捕获 InterruptedException 后优先沿允许的签名传播；本层结束且不能传播时恢复中断标记并终止/交给既定策略，不吞掉后继续无界循环。只有明确消费中断的框架边界可作例外；Thread.interrupted 会清除标记，isInterrupted 不会。
- ThreadLocal/诊断上下文在当前任务 finally 中按既有包装清理/恢复；线程复用时不能泄漏上一请求的身份、租户或日志标识。异步传递只复制必要可信信息，不默认继承事务和任意可变请求对象。
- 成功获得显式锁后在 finally 释放；未获得锁不 unlock。等待时间、可中断性、锁对象稳定性和顺序明确；volatile 只解决适用的可见性等保证，不使 count++ 或“检查再修改”原子化。多字段不变量用已有锁/原子条件保护。
- CountDownLatch 等协调器的参与任务在成功/失败路径均按约定完成计数，await 有预算与失败返回；任务根本未提交时同样处理。定时任务区分固定频率/固定延迟、重叠和漏跑；ScheduledExecutorService 的周期任务未处理异常可停止后续执行，不能据此误报 Spring/Quartz 等所有调度器行为相同。多实例副作用沿幂等/状态保护。

具体验收见 16.5；代理语义仍按 8.1。依据：[JDK Thread](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Thread.html)、[周期调度](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/ScheduledExecutorService.html)。

## 9. 远程调用、重试与降级

- 所有远程调用定义连接、读取和端到端超时，核验是否覆盖连接池等待、DNS、TLS 和读取。
- 超时依据依赖延迟和业务预算配置，分别评估查询、写入、下载；调用与重试总耗时不得超过入口或任务预算。
- 明确一个负责重试的层次，核对客户端、RPC、SDK、网关和任务配置，避免次数相乘。
- 对允许重试的暂时故障使用有界指数退避与抖动，限制次数、持续时间及总调用量；长期恢复保存进度并告警。
- 参数错误、权限拒绝、验签失败和确定业务拒绝不以同一请求自动重试；有副作用的写入必须先确认幂等契约。
- 写入超时不代表未执行，沿原操作查询；调用方不能擅自换业务号、主体或执行方规避不确定状态。
- 按依赖设置并发、排队和流量上限；定时任务适当错峰，不改业务截止时间。
- 降级需声明适用字段和过期容忍度；非关键展示可在授权范围内返回标明时效的缓存，权限、余额和执行结果不得返回假成功或默认值。
- 外部协议经适配层转换，保留原错误码和脱敏证据，禁止将空响应直接当作失败终态。
- 签名按正式协议绑定请求内容，验证证书、keyId、时间和防重放条件；验签成功仍需校验主体、资源和动作权限。

超时、重试和抖动参考 AWS Builders’ Library。是否可重试由具体操作语义决定，不因使用某个 SDK 就默认安全。[AWS 超时与重试实践](https://d1.awsstatic.com/builderslibrary/pdfs/timeouts-retries-and-backoff-with-jitter.pdf)

## 10. 数据库与 SQL

### 10.1 建模与访问

- 表与数据有明确领域 owner。跨中心不共享可写表；主档、快照、业务事实、投影和任务数据用途分开。
- 表字段小写下划线，注释写业务含义；金额、数量、时间和状态说明单位、时区及枚举。
- 主键、业务唯一键、查询索引基于真实访问设计；不为所有字段建立索引，不默认提前分库分表。
- 状态 version、对象内事件序号和投递游标分别定义；自增主键不等于提交顺序。
- UPDATE/DELETE 必须有明确范围和必要状态/版本条件；关键写入检查影响行数，不开放无条件批量操作。
- 禁止 SELECT * 和拼接用户参数；动态排序、表名等只能从固定映射白名单选择。
- 查询只读必要字段，分页稳定排序；导出分页或分批写入，禁止一次把全表装入内存。
- 大表、慢查询和深分页先分析执行计划，评估游标、索引和 count 成本；避免逐行远程查询及 N+1 访问。
- 核验 ORM 插件对自定义 SQL、批处理、乐观锁及数据范围是否实际生效。
- 删除主数据须检查业务引用和保留政策；资金、审批、审计等证据不得通过普通 CRUD 任意删除。

### 10.2 排查与数据变更

- 先确认环境、库、表和字段，优先 SHOW CREATE TABLE；生产排查使用只读账号，不执行写入或 DDL。
- 样例默认 LIMIT 20，禁止全库扫描；统计在数据库聚合，优先一条有明确范围的汇总 SQL，成本不可控时拆分说明。
- TEXT、JSON、BLOB 只返回长度或必要截断；禁止输出完整敏感载荷。
- 迁移和订正先交付复用正式 WHERE/JOIN 的只读预检，包含影响数及 LIMIT 20 关键样例；预检不等于写入授权。
- INSERT 检查候选和唯一键冲突；DDL 检查数据量、NULL、重复和旧版本兼容。实际执行使用独立授权变更流程。
- 涉及字符串比较先确认目标列 collation 和 @@collation_connection；CAST(... AS CHAR) 会继承会话排序规则，不能凭经验固定写死。
- 遇到 1267 不先改表；仅在已确认纯数字且可无损表达时数值比较，否则显式统一字符集和排序规则。
- 中间表继承源列排序规则，名称加 yyyyMMdd；提供明确清理步骤及保留条件。

### 10.3 MySQL 建表与结构变更

设计 MySQL 表、生成初始化/迁移 SQL 或审查 DDL 时，必须按 [MySQL 建表规范](mysql-schema.md)（DDL-001）执行。该文件集中维护命名、注释、字段与公共列、字符集、索引、约束边界、5.7/8 差异、只读预检、建表示例及验收，不在各 Skill 重复复制。

先确认业务事实、所有者和访问路径，再确定物理表。新业务表默认 InnoDB/utf8mb4/utf8mb4_general_ci，字符列继承表默认，列级例外须有契约依据；新内部 ID 用应用雪花 ID、不自增，公共时间列 create_time/update_time。保持存量主键、金额单位和项目比较契约，核验应用幂等判断与数据库一致。默认不建物理外键、不用级联删除或触发器承载业务；必要唯一约束、原子条件写入、事务及恢复不能省略。存量约定和已确认例外按专项规范处理，不因升级规范自动改表。

逻辑删除、回收站和恢复按 [逻辑删除规范](mysql-schema.md#41-逻辑删除字段读写与恢复)执行：适用表统一 deleted（0/1），覆盖查询过滤、映射、条件写入、主体权限、审计、并发与恢复占号。停用/撤销不等于删除，支付及审计事实不通过通用删除隐藏；不因字段存在就认定 ORM、自写 SQL 和派生缓存都已正确处理。

### 10.4 SQL 聚合与 ORM 映射

- 按含义使用 COUNT(*) 统计行、COUNT(column) 统计非 null 值；SUM 在无行或全 null 时可为 null。只有已确认“无数据视为 0”时用 COALESCE 或应用层精确转换，不能把未知金额/查询失败变成零。COUNT 可映射 Long 等足够范围类型；LEFT JOIN 的 COUNT(*) 不等于子表命中数量。
- 筛选、JOIN、逻辑删除和资源范围在 items/count/聚合中一致；先 count 再查并非跨语句一致性保证，不因 count=0 就断言此后必无数据。分页、并发变更与业务是否要求快照按真实契约核验。
- MyBatis 值参数使用 `#{...}` 等绑定，`${...}` 为未经转义的文本替换；动态表/列/排序不能靠绑定占位符当标识符，需将可信枚举映射到代码白名单。不能从请求拼接 SQL，也不要求删除有白名单且确需动态标识符的既有实现。
- 显式 SELECT 列及稳定别名映射到既定属性；DO/Entity、resultMap/resultType、JDBC 类型、时间/枚举/BigDecimal、可空与基本类型的转换用实际驱动/ORM 配置核验。复杂 JOIN 同名列不依赖偶然覆盖，Web 仍转 VO；不以“有注解”证明自写 XML 全部生效。
- 部分更新明确未提供/null/清空语义，并核验 ORM 的非空更新策略；不通过全字段覆盖把默认零/空值写回。更新有旧状态/版本条件时检查真实影响行数；影响数语义按驱动与项目配置核验，不能用“SQL 未异常”代替状态变更成功。

验收见 16.5，执行仍遵循 10.2 的只读与预检限制。依据：[MySQL 聚合](https://dev.mysql.com/doc/refman/8.0/en/aggregate-functions.html)、[MyBatis Mapper XML](https://mybatis.org/mybatis-3/sqlmap-xml.html)。

## 11. 缓存、配置与文件处理

### 11.1 缓存

Redis 的 Key、TTL、客户端/序列化、命令、锁、Stream、集群及恢复按 REDIS-001 读取共用 [Redis 专项规范](redis-standards.md) 的相关章节；第 11 节保留各类缓存均适用的基线，不要求普通业务新增中间件。

- 先证明存在访问或延迟问题，再复用已有缓存设施；缓存不成为唯一业务事实来源。
- 缓存键包含必要业务范围、对象标识和版本；禁止不同企业、角色共享未经裁剪的敏感结果。
- 明确 TTL、失效时点和可接受陈旧程度。数据库与缓存双写存在窗口，不能宣称天然强一致。
- 权限撤销、额度预算和执行终态不依靠过期缓存作最终批准；在权威边界重新校验或采用经过验证的一致性机制。
- 评估穿透、热点、集中失效及回源峰值；按实际风险采用限流、TTL 抖动或合并回源，不堆砌全部缓存模式。

### 11.2 配置

- 区分环境技术配置与版本化业务政策。费率、审批阈值、额度政策等变更有生效时间、责任人、审计及影响范围。
- 每个操作读取一致的政策版本；执行过程中不得混用热更新前后的值。
- 关键配置缺失或非法应启动失败或明确禁用能力，不能自动启用演示值；密钥由安全设施供给。
- 特性开关定义默认行为、适用范围、下线条件和关闭后的在途处理，不无限积累永久分支。

新增/修改配置按 CONFIG-001 核验类型化绑定的注册、校验提供者与嵌套约束，明确 Duration/数据大小等单位和允许范围；@NotNull 不保证超时为正。复用现有配置结构，单值不机械改成配置组。重命名键同步部署配置，使用实际 profile、环境变量或挂载文件的覆盖路径验证；文件改变不等于已刷新，需说明重启/轮换及在途行为。绑定对象和诊断输出避免通过自动 toString、日志或管理端点暴露凭据。实际版本和依赖以工程构建为准。

### 11.2.1 前后端连接配置与环境边界

实际有浏览器消费方时，记录 API 基址、服务端口、反向代理前缀、允许来源及各环境覆盖来源；使用已有配置和部署模板，避免多个默认值互相矛盾。服务间地址、容器内部地址和浏览器可访问地址分别确认；更改端口/前缀同步受影响消费方，不将开发 localhost 推广到部署环境。

浏览器可见配置只包含允许公开的值。带 VITE_/PUBLIC_ 等前缀不代表安全；禁止将服务端密钥、数据库凭据、内部令牌或仅供服务端使用的环境组导入客户端。配置样例说明必填项及环境用途，使用占位符；正式配置不能回退到示例账户、密码、受保护业务接口的任意来源放行或自动改表政策。沿 CONFIG-001 对缺失/非法值拒绝启动或按已确认政策禁用能力，不因使用生成器便默认正式环境安全。

**验收**：更改端口/代理前缀后由实际消费方请求业务接口；在适用环境验证允许与拒绝的 Origin、预检及凭据模式，并追加 AUTH-001 的会话/令牌与 CSRF 检查，不能只访问健康页。用虚构的敏感标记验证客户端构建产物及适用 source map 不包含服务端秘密；确认生产覆盖和必填配置的拒绝路径。无浏览器或无客户端构建时标为不适用；未连网关、浏览器或部署环境的项保留未验证，不导出真实秘密做检查。

### 11.3 文件与批量操作

- 上传校验类型、大小、内容及访问权限，文件名不直接决定存储路径；禁止路径穿越和将上传内容直接作为可执行资源。
- 导入有预检、模板版本、行级校验、重复策略、失败明细和审计；明确全批回滚或分批提交，部分成功不能显示全部成功。
- 导出按授权范围执行；异步结果下载时再次鉴权，限制保留期，防止可猜测地址泄漏。
- CSV/表格导出对不可信单元格处理公式注入；远程文件拉取限制目的地址、重定向及大小，防止越界访问。
- 文件和数据库不能组成普通本地事务；失败清理、重试和孤立文件回收有明确责任。

## 12. 事件、消息与后台任务

- 只有需要可靠传播的业务事实才采用持久化事件交付；普通进程内通知可使用简单机制，但必须标明可能丢失是否可接受。
- 可靠事件以 Outbox 或经过验证的等效方案解决业务更新与消息发送的双写窗口；仅提交后发 MQ 或事务事件监听不等于可靠交付。
- 消费端去重与本地更新同事务，提交后再 ACK；发生外部副作用时仍需对方幂等或原号恢复。
- Outbox 可能重复投递，不代表跨系统“恰好一次”。不为采用该模式强制引入特定云产品。[AWS Transactional Outbox](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)
- 集成事件包含稳定 eventId、类型、版本、来源、业务对象、身份范围、发生时间及所需事实；要求对象内顺序时另定义序号。
- 不序列化整个聚合、DO 或敏感主档发布。traceId、消息 offset 与业务幂等号具有不同职责。
- 消费者处理重复、乱序、缺口和旧版本；回放只重建投影，副作用入口必须有独立防重保护。
- 无法处理的消息进入可查询的失败记录或死信流程，有告警、责任人和受控重放；不能无限重试阻塞整条队列。
- 任务使用稳定分页、批量上限、领取租约、续跑位置和停机恢复；数据库游标与筛选条件变化一起设计，避免处理时漏扫。
- 人工补偿、导入、重投与在线入口调用同一业务用例；校验来源和权限，保留原因及结果，不开放任意脚本执行入口。

模块事件按 [Java 项目实践第 4 节](java-project-practices.md#4-状态机与事件不替代持久化保护)说明同步/异步事务和交付责任；提交后监听不自动提供持久化重投。使用可靠发布组件时验证实际配置、重启恢复及消费幂等，不再重复引入等价机制。

## 13. 身份、权限与数据安全

- 区分用户登录身份、服务身份、企业范围和业务主体；身份字段来自可信认证上下文，客户端传值需与授权范围核对。
- 每次操作校验身份、动作、资源归属和数据范围；网关鉴权、菜单权限或内网 IP 不能代替对象级授权。
- 授权规则由责任中心提供，各服务按统一语义执行；权限快照过期、撤销和缓存失效有明确策略。
- 缺失或无效上下文默认拒绝，不回退管理员或全企业范围。任务、RPC、消息和文件下载同样适用。
- DTO/VO 按端和角色裁剪，敏感字段不依赖前端隐藏；缓存、事件、报表和错误信息执行同样的数据边界。
- 密钥、口令、token 不进入代码、日志、示例和制品；轮换保留必要 keyId、有效期及兼容窗口。
- 签名、防重放、业务幂等和权限校验各解决不同问题，不能相互替代。
- 数据保留、脱敏、加密、导出与删除按分类和业务政策执行；安全删除不得破坏依法或按业务必须保留的审计证据。
- 依赖和镜像来源可追溯；发现高风险漏洞评估实际可达性、升级兼容与缓解措施，不用全局忽略掩盖问题。

修改浏览器跨域或安全链时按 AUTH-001 核验合法/非法 Origin、预检及实际请求的来源、方法、请求头和凭证策略，防止任意来源获得带凭证的跨域读取；CORS 不代替资源授权，也不能由一次 HTTP 200 推断生效。安全响应头按返回内容和浏览器风险采用，不复制固定 CSP 或仅因“无状态”就关闭 CSRF。实际有滥用风险的登录/公开高成本接口复用已有网关限流，验证拒绝语义，不强制引入限流依赖。

已接入 Actuator 或其他管理能力且本次涉及配置时，核验端点暴露清单、网络入口、匹配的安全链、操作角色和脱敏；独立端口/内网不等于授权。env、configprops、heapdump 和日志配置等敏感能力按最小范围开放，不因调试关闭全局脱敏；不同路径及角色分别验证。未接入时不因规范自动增加管理依赖。

## 14. 日志、审计与可观测性

- 日志使用统一门面和参数化输出；禁止 System.out、printStackTrace、吞异常和重复无意义 ERROR。
- 关联 traceId、服务/用例、必要身份范围、业务号、结果类别和耗时；跨 HTTP、RPC、消息和任务持续传递关联信息。
- 不默认打印完整请求响应、证件、银行卡或凭据。确需保留原始证据时加密限权存储，日志仅记摘要及引用。
- 技术日志与业务审计分开；审批、权限调整、金额变动、业务配置、人工恢复记录操作者、理由、前后值或版本。
- 审计记录具备可追溯及防随意篡改措施，不能依赖可采样、随时清理的普通日志。
- 按服务职责定义成功率、延迟、错误率、资源饱和度，并补充积压、重复、未决和处理时效等业务指标。
- 指标标签使用受控维度，不把订单号、用户 ID 或 traceId 作为高基数标签；明细通过日志和追踪关联。
- 告警说明业务影响、阈值依据、责任人和处置步骤；避免每次重试都通知。SLO、恢复时限及数据恢复目标按业务确认，不全系统统一拍定数字。
- 健康检查区分进程存活和是否可接流量；依赖短暂故障不应触发无意义的进程重启风暴。

探针和管理端点按 OBS-001、AUTH-001 验证实际输出与访问范围；用虚构敏感值检查脱敏，不打印真实环境变量值或完整绑定对象。liveness 不依赖普通远端故障，readiness 根据项目接流量政策定义必要依赖与检查超时，健康详情也执行数据边界。不为完成检查预造监控平台。

### 14.1 日志的运行验收

- 占位符避免普通字符串拼接，但 `log.debug("{}", expensive())` 的方法仍会先求值；昂贵查询/序列化按已用日志 API 的开关或惰性方式执行，不能为日志再查大表或触发业务副作用。
- 文件日志按部署预算配置滚动、保留期、容量上限与磁盘告警；容器标准输出由现有采集链承担这些职责。业务日志、审计与安全留存按已确认政策分别确定，不把嵩山版示例天数当现行法规或所有项目的固定要求。
- 核验多 appender/additivity、重试与异常边界是否重复记录，异常带必要 cause/堆栈和安全关联字段。标准日志框架输出 stdout 可用，不与 System.out.println 混淆；日志采集失败不能隐藏需可靠保存的审计事实。

验收见 16.5；敏感数据、换行注入和管理端点另按 OBS-001。

## 15. 格式检查与工程质量门禁

| 检查范围 | 基线 | 落地方式 |
| --- | --- | --- |
| 编码与格式 | UTF-8、LF、Java 4 空格/120 字符；YAML、JSON、XML 2 空格 | EditorConfig、Checkstyle、统一 IDE 规则 |
| 常见 Java 误用 | 空指针、资源泄漏、集合、equals/hashCode 等 | P3C 或已有静态分析 |
| 对象与模块边界 | Query/DTO/VO/DO 隔离，无循环依赖，契约不泄漏实现 | 依赖检查；必要时补充最小架构规则 |
| 接口与安全 | 契约兼容、权限边界、凭据与依赖风险 | 契约验证和已有安全工具 |
| 行为正确性 | 核心断言、竞争、失败和恢复 | 按业务风险选择可重复验证 |

- 工具、插件、规则集和分析引擎版本统一管理，核验 Lombok 注解处理器、文本块及当前 JDK 兼容性。
- IDE 和构建使用相同规则；检查必须绑定实际流程，只声明版本不算启用。
- 复用已有工具，不因每条规则新建一个平台。工具覆盖不到的业务要求进入评审。
- 告警例外有最小范围、原因、负责人和失效条件，禁止全工程关闭检查。
- 格式检查通过不证明授权、事务或业务状态正确。

### 15.1 集合与 Stream 调整要保留可变性契约

新增集合返回值、替换收集 API 或修改调用方时，沿调用链核验是否会增删、替换或排序，不因语法更短改变已有契约。

| API | 需要核验的语义 |
| --- | --- |
| Stream.toList() | 返回不可修改列表，增删或 sort 等修改会抛 UnsupportedOperationException；只读调用方可以直接使用 |
| Collectors.toList() | 不保证实现类型、可变性、序列化及线程安全；不能断言它必为 ArrayList，也不能仅凭 API 名称判定本次已经抛异常 |
| Collectors.toCollection(ArrayList::new) / new ArrayList<>(已有集合) | 需要明确可变列表时采用；不额外增加工具类或依赖 |

不可修改列表不保证元素本身不可变、线程安全或资源隔离。已有 null、顺序和序列化语义分别核验；缺少修改调用方时不为“将来可能修改”复制集合，也不把使用 Stream 或普通循环作为风格缺陷。

正反例与验收：把仍需 append/sort 的返回值改成 Stream.toList() 是行为回归；明确可变收集后用同一修改操作复验。只读返回 Stream.toList() 是正常样本。范围包含空集合、正常输入及实际修改路径；编译通过不证明可变性未变。依据：[JDK 21 Stream.toList](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/stream/Stream.html#toList())、[Collectors.toList](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/stream/Collectors.html#toList())、[List](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/List.html)。

## 16. 测试与验收

### 16.1 按本次行为选择验证

- 验证实际入口的正常路径、边界输入、空值/缺失、无权限和跨主体访问；有写入时追加重复和并发修改。
- 有外部依赖、后台任务或持久状态时，追加超时、响应异常、中断和重启恢复；所有接口的错误提示符合契约。
- 数据查询的稳定排序、范围隔离和大批量限制。
- 新旧请求、响应、事件和数据结构共存，发布与回退版本能否处理在途操作。

验证范围按 [Java 项目实践第 5 节](java-project-practices.md#5-测试证明什么就报告什么)选择；MVC/mock、真实存储、模块与外部协议证据分开。回滚型测试不能替代 after-commit 及真实提交场景，测试注解和依赖版本按项目基线核验。

测试应自动断言、互相独立并可重复：不依赖执行顺序、真实当前时间、前一用例残留数据或外部随机状态；必要夹具在隔离环境建立并清理。边界、正确、错误和约束条件按行为选择，测试权限、金额、并发时断言副作用和持久化结果；不要仅打印结果或验证 mock 被调用。覆盖率用于发现遗漏，不把统一 100%/固定比例当业务正确性的证明。测试文件是否进入 Git 沿目标项目约定；本项目仅本地保留验证文件。

### 16.2 按能力追加验证

| 能力 | 必验场景 |
| --- | --- |
| 主档与权限 | 并发更新、授权撤销、组织变更、角色越权及缓存失效 |
| 审批与订单 | 重复提交/审批、审批版本失效、状态冲突、取消与完成竞争 |
| 库存/资源预占 | 并发超占、确认与释放竞争、超时恢复、重复归还 |
| 账户与金额 | 单位、精度、溢出、预算、分录一致性及原操作逆向 |
| 支付 | 执行成功但响应丢失、迟到回调、原号查询、退款预算及未知结果 |
| 结算对账 | 重复文件/批次、缺数、迟到事实、舍入尾差、账单修订和核验冲突 |
| 消息与任务 | 重复、乱序、ACK 丢失、租约过期、重放及断点续跑 |
| 导入导出 | 越权、恶意内容、重复导入、部分失败、容量和下载有效期 |
| 包/Mapper 资源移动 | 干净构建、无旧类残留、预期扫描/装配数量、类名及资源引用、字段/业务/SQL 差异和受影响行为 |

验证输入、制品、结果与源码版本及环境绑定，可供他人复验。涉及 MySQL 锁、排序规则和事务时使用隔离的 MySQL 环境；仅 mock 仓储或使用替代数据库不足以证明真实语义。

常用命令按检查范围选择，完整流水线可由 verify 执行已绑定阶段，不需机械重复全部命令：

```bash
mvn -q -DskipTests compile
mvn -q -DskipTests test-compile
mvn -q test
mvn -q verify
```

报告分别记录编译、测试编译、实际测试数量和断言、静态检查、集成验收与未覆盖范围。-DskipTests 跳过测试执行；-Dmaven.test.skip=true 通常还跳过测试编译，需核验插件配置。零测试或仅编译成功不能表述为业务验证通过；模拟接口不代表外部系统联合验收。

### 16.3 缺陷修复与性能回归

按 BUG-001 记录源码与实际运行制品版本、环境、触发输入、实际/预期结果，先取得失败证据，再追踪入口、调用方与数据来源。一个假设对应一次最小验证，确认根因后在共享责任点修复，并以原断言及受影响正常/异常路径复验。确定的编译错误使用编译失败证据即可，不为此增加测试框架。

偶发或外部问题无法复现时，说明已调查范围和缺少条件；不把缓解措施、编译成功或本地模拟称为生产根因验证。重复失败后重新检查假设、配置和部署制品，禁止堆叠修补或自动扩大重构。性能回归使用相同负载/数据范围与可重复指标前后对照；临时脚本按项目要求仅保留本地。

### 16.4 规范包与智能体评测

规范文件、代码行为和智能体执行分别留证据：发布前检查版本、规则引用、安装映射与 ZIP 内容；客户端发现测试在新会话中确认规则是否可见；模型遵循测试用固定任务与基线评判；实际生成代码仍需构建及行为验证。主动向模型提供 Skill 内容不证明客户端自动发现，模型进程成功退出也不等于评测通过。

记录模型、客户端/工具版本、规则来源提交或制品哈希、工程基线与工作区状态、固定输入、产物、判定证据和未完成项。通过、失败、待核实和未执行分开；保留失败结果，同条件重复后再比较。评测只在指定临时副本与隔离依赖中运行，不自动调用模型、部署或写真实业务数据。具体流程见开发 Skill 的初始化指南，维护材料位于本规范包 evaluations/README.md。

### 16.5 常用场景的具体验收

沿已有测试/验证方式选择本次对应行，无需为小改动引入框架；使用真实数据库/Redis 的场景仅在获准的隔离环境运行，不用生产试错。

| 场景与条款 | 输入或故障条件 | 必须断言/证据 |
| --- | --- | --- |
| Maven（3.6） | 冲突传递版本；仅放 dependencyManagement/pluginManagement；打包运行环境 | 实际依赖树/有效 POM、插件执行与包内类一致；运行所需依赖真实存在，不用 IDE 通过替代 |
| 执行器（8.2） | 任务阻塞至队列满；提交拒绝；关闭期间提交；一个任务失败 | 既定拒绝/错误结果与指标，线程/队列/在途预算不失控；不返回伪成功；关闭有界 |
| 取消/上下文（8.2） | 等待超时后任务继续；任务中断；同一工作线程顺次处理 A/B | 超时不误称已撤回副作用；中断政策可观察；B 看不到 A 的身份/租户/日志上下文 |
| 锁/协调（8.2） | 获锁后业务抛错；未获锁；一个参与任务失败/未提交；并发增量 | 持锁路径释放、无权不解锁；等待可结束并表达失败；增量/状态满足实际原子不变量 |
| 定时任务（8.2） | 首次执行异常；单次超过周期；多实例重叠/重启 | 当前调度器后续触发与重叠政策有证据；重复副作用被保护，不靠 sleep 判定调度完成 |
| SQL 聚合（10.4） | 无行、全 null、部分 null；LEFT JOIN 无子项；大 COUNT | 行数/非空数/合计口径正确，null 不意外拆箱；无数据归零有政策，类型不溢出 |
| ORM/更新（10.4） | 同名 JOIN 列；精确金额；缺失/null/显式清空；旧版本条件不匹配 | 真驱动映射与精度正确；只改变授权字段；零影响按冲突/不存在政策返回，事务行为另验 |
| SQL 输入（10.4） | 文本值含引号；未允许的排序/表列；普通已允许排序 | 值被绑定；标识符白名单拒绝；正常查询不误报；保留范围条件及计划证据 |
| 日志（14.1） | 关闭 debug；一次异常穿过多层；滚动上限；虚构敏感值/换行 | 昂贵参数不求值；有责任边界记录；容量/采集政策生效；无敏感泄漏或伪造记录 |
| 测试独立性（16.1） | 单独执行、不同顺序、重复执行；固定时钟；污染夹具 | 结果与断言一致，残留可清理；实际测试数及失败记录可查，零测试不算通过 |
| JVM/发布（18.1） | 实际容器限额、受控负载、停止信号；dump/日志接近预算 | 堆/非堆/线程/连接有余量；GC/错误与探针可定位；排空有界，敏感诊断文件受控 |
| Redis 计数/一次性凭据 | 首次计数后失联、窗口边界；错误凭据与并发成功消费 | 按 [Redis 3.1](redis-standards.md#31-计数限流与一次性凭据) 检查 TTL、原子条件、次数与恢复，不以 mock 证明故障窗口 |

### 16.6 能力证据等级与交付制品

按 CHECK-001 描述本次实际能力及其证据范围；已有项目复用当前交付记录，不新增固定报表平台。采用生成器时区分以下等级，手工实现无需为了等级流程额外生成工程。

| 等级 | 可以证明 | 不能由此推定 |
| --- | --- | --- |
| 已定义 | 选项、契约或组合约束已明确 | 文件已生成、依赖已引入 |
| 已生成 | 固定输入产生预期文件，结构核对通过 | 安装、编译、启动或业务成功 |
| 构建验证 | 干净工程按记录的工具链完成声明的安装/编译/打包/测试阶段 | 服务已启动、浏览器与外部协议可用；跳过测试不算测试通过 |
| 运行验证 | 实际进程在记录环境通过明确的协议和行为断言 | 未覆盖能力、真实外部联调、完整业务或生产验收 |

真实联调、业务验收和上线验收继续按第 18 节分别记录，不合并为“运行通过”。证明只覆盖实际断言命中的选项/入口；健康页成功不提升认证、存储、缓存或事务的证据等级，H2/mock 不能提升为 MySQL/Redis 验证。

记录源码提交及工作区差异、生成输入、模板/依赖版本或哈希、工具链/环境、命令和断言结果、日期及范围；未提交内容可用实际文件/制品哈希绑定，不伪造来源 SHA。缺失、失败、跳过、版本/输入不匹配的记录不能用于本轮通过结论；源码、模板或依赖改变后按影响复验，外部环境或已定有效期变化时重新核验，不机械套统一 30 天期限。

交付 ZIP、JAR 或已发布脚手架包时，在隔离目录验证实际制品的展开/安装和适用构建、启动入口，不能只测试源码仓库；记录制品哈希。仅规范文档分发按包检查验证内容、引用和字节一致，不为此运行 Java/模型。工程生成还应核对保存配置与产物一致、无残留模板标记，以及本次支持/拒绝的组合；保持失败证据。验证记录描述已经执行的阶段，不能因存在测试文件、命令或配方就标为通过。

## 17. 代码审查与团队协作

- 一次评审围绕一个完整业务目的，重构和行为变更尽量分开，避免无关格式改动。
- 变更说明包含触发场景、前后行为、影响模块及调用方、验证证据、兼容风险和恢复方案。
- 审查设计、正确性、复杂度、校验、命名、注释和文档，明确未覆盖范围。
- 意见分为阻断问题和建议；正确性、安全及强制规则必须解决，个人审美偏好不作为阻断条件。
- 跨中心契约由提供方及受影响消费方共同确认；资金、权限、迁移和政策变更由相应责任人专项复核。
- 修改后重新核验受影响结论；不得用旧版本的通过记录证明新增变更安全。
- 开发交付对应“需求/规则 → 修改点 → 验证证据 → 未覆盖项”；简单变更简短说明，复杂变更再列表，审查覆盖记录不代替行为断言。

以上协作方式参考 Google 的[小变更原则](https://google.github.io/eng-practices/review/developer/small-cls.html)和[审查关注点](https://google.github.io/eng-practices/review/reviewer/looking-for.html)。

合并前至少回答：职责是否正确、Query/VO 边界是否清晰、数据是否越权、状态是否可并发保护、失败是否可恢复、SQL 是否有界、契约是否兼容、验证是否真实；金额及其他专项检查按第 19 节追加。

## 18. 发布、迁移与运行交付

- 各中心维护依赖和消费者清单、配置及迁移前提、上线顺序和回退条件，不依靠口头约定同时发布。
- 数据与接口采用兼容扩展、迁移验证、消费者切换、最后收缩的步骤；删除旧字段和旧契约前证明已无依赖。
- 发布前确认版本、配置、数据库预检、检查结果、容量影响和负责人；灰度范围及观察指标按风险确定。
- 停机先停止接收新任务，合理排空在途工作并保存恢复位置；新旧任务执行者通过租约和幂等防止重复副作用。
- 回退不只恢复应用版本，还评估新数据、新状态、新事件和已发生外部操作；不可逆变化使用前向修复或专项恢复。
- 补数、重算和历史迁移有范围、总量核对、唯一键保护、断点、审计与停止条件，不混入正常请求隐式执行。
- 运行交付包含依赖故障处置、数据恢复和关键业务查证步骤。构建成功、服务启动、页面可访问与业务验收分别记录。
- 上线验收覆盖关键用例与跨中心实际结果；无证据不得宣称完成生产验证。

### 18.1 JVM 与运行资源

- JVM 参数和容器资源从当前 JDK/部署配置核验；堆之外保留 Metaspace、直接内存、线程栈、代码缓存、native 与进程余量，不把 Xmx 设为容器全部内存。Xms/Xmx 是否相同按负载和设施决定，不抄固定比例或旧 GC 参数。
- GC/异常日志、OOM heap dump 的开关、路径、权限、轮转/容量按设施策略；dump 可能含凭据和业务数据，采集/转交须受控。容器被系统 OOM kill 不保证 JVM 来得及生成 dump，不把“没 dump”当没有内存问题。
- 线程/连接池、文件描述符、临时文件、磁盘与缓存预算一起检查；以当前负载、已有指标和诊断定位瓶颈，不机械套旧 TCP/内核调优。诊断命令的目标进程和输出范围先确认，不导出真实敏感环境全量内容。
- 停机信号经入口摘流、在途等待/任务退出、资源关闭与恢复交接，时间预算同容器终止宽限期协调；被强杀/重启后的幂等、租约和任务恢复沿对应规则。只通过编译不等于发布验收。

依据：[JDK 21 java 命令](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html)；运行验收见 16.5，不为规范更新修改实际 JVM/部署配置。

## 19. 业务专项规则

本节按实际职责采用。一般查询、字典、内容及配置功能不需要实现资金模型；高风险能力也不能以“通用规范已通过”为由省略专项保护。

### 19.1 用户、组织与权限

- 身份、组织归属、角色授权各有唯一主档；其他中心保存必要引用或授权快照，不能自行扩权。
- 主体停用、组织迁移和授权撤销说明对登录态、服务凭证、任务、缓存和在途操作的影响。
- 登录账号、企业主体、商户主体和接入应用分别建模，禁止以相同名称替代授权关系。
- 关键授权变更具备审计和批准依据，防止操作者给自己超范围授权；历史业务保留当时责任主体及必要版本。

### 19.2 订单、审批及库存类能力

以下按目标项目实际能力采用，不代表必须新增对应中台。

- 订单价格、履约和售后由相应业务负责，执行中心不得根据技术响应自行批准业务。
- 审批绑定对象、内容或版本、批准范围、有效期和授权人；审批后的关键内容改变应重新校验批准有效性。
- 审批重复回调只应用一次，撤销与执行竞争有明确仲裁和条件更新。
- 库存或资源扣减需明确可用量、占用量、确认及释放语义；并发防超占，预占成功不等于履约完成。
- 超时后是否释放取决于权威执行结果；不因任务扫描次数达到阈值就释放已可能消耗的资源。

### 19.3 金额、额度与精确计量

- 人民币现金金额通常以整数分表示；多币种按币种契约定义最小单位，不默认所有币种都是两位小数。
- 费率及中间计算使用 BigDecimal，明确单位、尺度和舍入政策版本；禁止每个 Service 自选舍入方式。
- 外部“元”字符串显式精确转换，不足最小单位或溢出时拒绝；整数运算使用范围校验或 exact 运算。
- 现金、业务额度（如易货额度）和其他资源数量分别计量，未确认换算依据前禁止相加为余额、利润或开票金额。
- 建立业务意图时固定适用的金额、币种、主体、报价、费用及批准版本。历史事实不因主档更新自动重算。
- 尾差、分摊和最后一笔处理给出批准政策及算例；现金流方向、商户服务费和机构成本不能混用。

### 19.4 资金账户

- 账户容器创建不等于授额；额度、权益和义务变化必须有可核验业务依据和唯一操作号。
- 可用、预占、待结算及已确认权益分别定义；在同一原子边界内校验预算并登记对应账务变化。
- 预占确认与释放互斥，未知扣减先查原号，不以超时直接释放。
- 划转及对应分录保持已确认的计量平衡和一致性，依据资产/单位核对，不将所有权益强行等同现金。
- 后续分配只能使用原交易已扣减份额，禁止重复扣买方；其他中心不直接修改余额。
- 逆向引用原操作及原分录，生成新事实；禁止删除流水、直接改余额抹平差异。
- 现金清偿核销依赖实际收款证据，不能以支付受理或上传凭证代替。

### 19.5 支付

- 支付意图、尝试、机构请求号、机构交易号和通知状态分别建模；建单固定报价、币种、收款主体、产品及原路由。
- 业务付款号按已确认企业与应用范围幂等；机构执行沿原尝试固定请求号，同号异参拒绝。
- 同一意图不允许多个活动资金尝试。现金未知不能切额度，额度未知不能切现金；重试不换主体或通道。
- 原文验签后仍校验商户、金额、币种和原订单关联。前端跳转或不可信消息只能触发查询，不能确认成功。
- 超时、断连和不可判定响应进入 UNKNOWN；查询原号，只有机构契约允许时才原号幂等重试。
- 已成功不被迟到失败回退；相反终态进入核验。关闭请求不等于已关闭，迟到成功不得丢弃。
- 退款绑定原支付、批准依据和稳定退款号。并发预算覆盖已退款与所有未决占用，申请和占用原子提交，UNKNOWN 不释放。
- 分账逆向和消费者退款分别编号、分别查证，原交易门闩防止并发冲突；规定前置条件未满足不得先退款。
- 支付成功不因退款被抹除；旧系统交易沿原责任系统恢复，不能任意迁入新中心重新执行。

### 19.6 结算对账

- 结算计划固定原交易、合同/费率版本、接收方、用途和计量单位；计划生成不等于执行或到账。
- 同单分配与退款逆向由权威方维护互斥和预算，未决保留占用；共享 Redis 锁不能替代跨中心协议。
- 账期明确时区、截止点、迟到事实及重算政策；已确认账单修订形成新版本或调整记录，不覆盖原证据。
- 文件或批次具备来源、校验、版本和重复处理规则；导入成功不等于核对无差异。
- 区分缺失、重复、金额/状态不符和到账差异，保存稳定关联键、责任人及处置证据。
- 支付终态、账户分录、机构结算批次、银行到账和商户账单分别核验，不能将其中一项视为其他项完成。
- 差错处理发出受控纠正指令，由事实所属中心产生调整；对账服务不得跨库改支付单或余额“对平”。
- 服务费应收与实收核销分开，上传凭证或账单确认不等于真实收款。

### 19.7 其他中台与新能力

新增业务能力先交付：术语、主档和事实 owner、关键不变量、接口与事件、权限范围、重复/并发策略、失败恢复及专项验收场景。

通知、搜索、报表等支撑能力按职责保留派生状态，不获得修改原业务事实的权限。计费、营销、风控等新领域的政策、事实及执行责任单独确认，禁止借公共工具包或“通用审批”隐式扩展业务边界。
