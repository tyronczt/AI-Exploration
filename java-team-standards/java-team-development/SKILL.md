# Java 团队规范开发

在编码前采用规范，在实现中落实约束，在交付时验证。此技能与 `multi-center-code-review` 随规范包一起安装，共用 [完整开发规范](../multi-center-code-review/references/standards.md)，不要求使用者再复制一份规范。

## 开发前

- 确认需求、目标模块和当前变更，读取目标项目 AGENTS.md 及路径上的补充规则。项目已有明确约定优先；不能根据通用示例推定业务事实。
- 从入口追踪必要调用链，找到现有相似实现、对象转换、异常处理及构建命令；不扫描无关模块。
- 先读完整规范的目录，再加载当前任务相关章节：接口与对象 3～6，状态/事务/远程调用 7～9，SQL/缓存 10～11，事件与任务 12～14，验证交付 15～18，多中台边界 2 与实际适用的 19.x。编号变化时按标题定位。
- 规范文件缺失时明确说明；先读取目标项目其他已确认规则，不编造团队要求，也不声称完整规范已加载。
- 修改前简述文件、实现方式和风险。复用现有实现及 JDK/Spring 能力，只对任务需要的代码作最小修改。

## 编码中

- Web 请求为 Query、响应为 VO，Controller 完成 Query → DTO、DTO → VO 的纯转换；DTO 用于内部传输，不泄漏 Entity 或 ORM 分页对象。字段注释明确业务含义、单位和状态取值。
- 入口校验参数、动作权限及资源归属；Service/应用层编排用例，领域层维护实际不变量，Mapper/Repository 访问数据。简单 CRUD 不强制增加领域模型或接口层级。
- SQL 有界且考虑索引，分页排序稳定；并发修改通过业务唯一约束、条件更新/版本等实际机制保护，并检查影响行数。
- 对有副作用的操作明确幂等范围、事务边界、状态变迁和失败恢复。涉及远程调用时明确超时、有限重试和结果未知时的查证方式。
- 一个业务事实只有一个权威写入方；跨中心使用明确契约。普通用户、配置、订单、库存与报表按各自需求采用专项；金额精确计量，不把所有业务套成支付流程。
- 不擅自修改公共 API、数据库结构或引入依赖；确属任务需要时说明影响，在已有授权范围内推进。业务依据不明时只提出具体待确认项。

## 交付前

- 针对本次改动核对正常、参数异常、越权、重复、并发及失败路径中实际适用的情况；不是每个 CRUD 都要完整资金审计。
- 按真实工程执行适当构建与验证；有 Maven 主代码改动时优先 `mvn -q -DskipTests compile`，行为/安全/并发改动追加针对性验证。说明跳过或无法运行的项，编译通过不等于测试通过。
- 输出改动文件、核心行为、验证命令及结果、影响与剩余风险。测试文件是否提交遵循目标项目规则。
- 用户明确要求独立代码审查时再读取审查 Skill；不要把普通开发变成只给问题清单、不完成实现。安装或使用此技能不授予提交、推送、数据库写入或生产发布权限。
