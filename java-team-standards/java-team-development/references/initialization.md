# 初始化决策与验收

没有真实业务模块时，先确定一个能运行和验证的工程切片。不要从“多个中台”直接推导出多个服务、多个数据库或统一基础框架。

## 1. 在项目中留下已确认的决定

使用项目已有决策文档；没有时，在用户授权初始化方案或工程后生成 `docs/engineering-baseline.md`。安装规范不会自动创建它。每项记录“值 / 已确认、建议或待定 / 依据与日期”，未决项可以保留，不伪造确认。

| 决策项 | 要写清的内容 |
| --- | --- |
| 技术基线 | JDK、Spring Boot、构建工具的具体版本；兼容性核验 |
| 工程形态 | 根包、实际模块、部署单元；先单模块或模块化单体的依据 |
| 数据访问 | 数据库、ORM、迁移工具；未决定时不引入依赖或生成空 Mapper |
| MySQL 表结构 | 精确版本、ID 策略、引擎/字符集/collation、时间约定、表职责及字段/索引；生成 DDL 前读取 [DDL-001 建表规范](../../multi-center-code-review/references/mysql-schema.md)，不自动堆叠外键或触发器 |
| Web 契约 | 普通 class + Lombok、Query/DTO/VO 位置；业务请求参数超过 3 个用 POST JSON，3 个及以内的简单只读查询可用 GET；参数计数及复杂结构按完整规范 6.2；响应包装、HTTP 状态与错误码 |
| 序列化契约 | Serializable/UID 团队约定；实际 JSON/RPC/缓存/消息序列化器、构造绑定、泛型与新旧读取策略 |
| 分页 | 页码起点、默认值、字段缺失/null 与缺失请求体策略、上限、越界策略、总数口径、稳定排序；验收见 WEB-002 |
| 权限 | 身份来源、动作权限、资源归属、适用的 CSRF，以及查不到与无权访问的返回政策；不直接照搬教学认证配置 |
| 副作用 | 哪些操作写事实；事务、幂等键、重复结果和失败恢复的责任方 |
| 中间件 | 现有需求与引入依据；不因“以后可能需要”引入 MQ、Redis 或分布式锁 |
| 工程检查 | 实际可运行的编译、格式/方法 Javadoc 检查和行为验证命令；人工或智能体核对注释是否符合真实行为 |
| 例外 | 规则编号、原因、替代保护、负责人和复核条件 |

在 AGENTS.md 受管区块外补充版本、命令和决策文档链接；不要复制整份决策文档。团队格式规则和业务政策分别维护。

## 2. 最小参考工程

源码位于 [examples/reference-service](https://github.com/tyronczt/AI-Exploration/tree/main/java-team-standards/examples/reference-service)，独立 ZIP 同时包含它。仅安装规范不会复制或运行工程；用户明确要求初始化/运行参考工程时，从同一版本包取出。

这是 Java 21 + Spring Boot 3.5.16 + Maven 的单模块、只读组织查询示例。它演示 Query → DTO → VO、分页、校验、统一错误和动作/资源权限；组织仅为教学对象，不预设真实中台职责。

示例分页保留已确认的 `POST /api/reference/organizations/page` JSON 契约，演示请求体绑定和 CSRF；当前仅有两个分页参数，不表示分页必须 POST。新接口按业务参数数量选择；详情使用 GET。示例契约：响应 `code/message/data`；成功码 `OK`；分页 `pageNo` 从 1 开始，默认 20 条，上限 100，超限拒绝，按创建时间降序再按 ID 降序；列表 `items/total/pageNo/pageSize`。这些是示例已定值，新项目须单独采用或调整。

身份采用环境变量密码和 Spring Security HTTP Basic，仅绑定本机。正式系统应接入已确认身份服务；内存数据不证明 SQL、事务、持久化幂等或生产认证已完成。

## 3. 工程验收

- 编译、打包与静态检查成功；故意加入星号导入后检查失败，恢复后重新通过，证明检查实际执行。
- 实际启动并发送 HTTP 请求，验证 Query 绑定、分页默认/边界/非法值、稳定排序、统一错误。
- 未登录访问令牌/详情接口得到 401；POST 先验证 CSRF，缺失或错误令牌得到 403，合法令牌再检查认证与动作权限；不同企业互不可见；跨企业详情与不存在资源采用同一 404 策略。
- 明确记录测试数量。示例没有提交自动测试文件，不把 Maven 的零测试报告成“测试通过”；行为验证步骤见工程 README。
- 引入数据库或写入后，再用选定数据库验证唯一约束、条件更新、回滚、并发、幂等及异常恢复。参考工程的结果不覆盖这些项。

## 4. 验证规范是否真能帮助智能体

后续使用同一模型、工具、输入和基线，分别在有/无本规范的干净目录执行；每例建议重复 3 次，保留失败，不仅展示最佳输出。小样本只反映当前条件。

| 编号 | 给智能体的真实任务 | 验收要点 |
| --- | --- | --- |
| E1 开发 | 给参考列表增加名称筛选 | Query 校验、DTO 转换；筛选和 total 均保留资源范围 |
| E2 开发 | 给详情增加展示字段 | VO 字段来源与注释准确；不暴露内部资源归属字段 |
| E3 审查 | 在临时副本删掉资源过滤，要求审查 diff | 指出 AUTH-001、真实行号和越权输入；不提示预设答案 |
| E4 审查 | 审查正常的只读实现 | 不要求 Outbox、幂等表、DDD 空层；没有证据不凑问题 |
| E5 安装 | 首装、重装，再手改受管文件后更新 | 无重复区块；原有内容保留；冲突不覆盖、不部分更新 |
| E6 DDL | 分别为 MySQL 5.7/8 设计商户请求记录表，再审查其唯一性和状态更新 | 新内部 ID 不自增，公共时间列 create_time/update_time；字符列继承表默认，ASCII/bin 例外有协议依据；金额单位及存量主键不被模板改写；验证大小写/尾空格幂等、主体范围内唯一；不滥用外键/触发器，说明 CHECK 差异和未验证项，不执行业务库 DDL |
| E7 逻辑删除 | 为已有管理表实现删除/恢复，并审查自写 JOIN 与业务号复用 | deleted 由服务端控制；过滤、权限与审计完整；删除竞争、重复请求、重建再次删除及恢复占号有验证；不向支付事实表机械加列，不声称注解覆盖所有 SQL |

记录规则遗漏、误报、返工、用时及可取得的 token/费用；每种客户端分别核验发现和引用。上述是评测方案，工程 smoke 验证不等于已经完成这组智能体对照评测。

## 5. 如何维护

真实任务反复出现且能复现的问题才升级为规则，单次偏好不自动写进 AGENTS.md。短入口保留导航，细节只维护在共用参考中。新增规则先给编号、适用条件、反例和验收；工具升级后复验受影响路径。

采用依据：[Spec Kit 计划模板](https://github.com/github/spec-kit/blob/main/templates/plan-template.md)用于记录技术上下文和复杂度依据；[HumanLayer 指令维护实践](https://www.humanlayer.dev/blog/writing-a-good-claude-md)用于短入口与按需读取；[上下文文件评估研究](https://arxiv.org/abs/2602.11988)提示需要实际任务对照，不能宣称增加规则必然提高效果。
