# 小天动作与场景提示词库

## 使用方式

沿用 [角色规范](character.md)、[认可九宫格](../assets/character-style-reference.png) 和 [正面细节参考](../assets/character-front-reference.png)。九宫格对应 A01–A09；S01–S10 是新增场景文字方案，尚无独立认可图片。

可以直接请求：“使用小天 A04 指向讲解，人物放左侧，右侧留白，16:9。”Agent 将下面的通用前缀、选中条目与交付要求合成为一段完整提示词，不把编号单独发给图像工具。实际查看并附上参考图片；路径按技能安装位置解析，不依赖历史聊天。

每次选一个主动作。画面位置、道具、景别按请求覆盖默认值；人物自身左右与画面左右分别说明，不能靠整图镜像改变指向，否则腕带会换边。未指定时交付单人静态图；视频另加运动段并执行 [视频指南](../video/GUIDE.md)。

## 先查图片，再组装提示词

收到人物动作请求时先执行素材查找，不能略过图片索引直接凭名称生成。用户给编号时精确查找；给自然语言时按下表关键词定位系列，再查该系列的动作名称和描述。选中后实际查看图片，核对对应格子。关键词只是检索线索，不覆盖文章中的事实与状态。

| 系列 | 检索关键词 | 对应图片（相对本文件） | 动作说明 |

同一系列内编号后两位对应格子：

| 尾号 | 图片位置 |
|---|---|
| 01 / 02 / 03 | 第 1 行第 1 / 2 / 3 列 |
| 04 / 05 / 06 | 第 2 行第 1 / 2 / 3 列 |

例如“修复 bug”匹配 **D05**，使用 `../assets/character-actions-debug-network.png` 的 **第 2 行第 2 列**；“发布完成”匹配 **R08**，使用 `../assets/character-actions-integration-release.png` 的 **第 3 行第 2 列**。不要把“发布中”R07 与“发布完成”R08 混用。没有精确匹配时列出最接近的 1–2 项及差异，不编造已存在的素材。

查找后输出简短素材卡：

```text
动作：D05 · 修复 bug
图片：将 ../assets/character-actions-debug-network.png 解析为当前安装目录下的真实路径，并提供可点击图片链接
位置：第 2 行第 2 列
身份：原认可九宫格 character-style-reference.png；细节按需使用 character-front-reference.png
提示词：通用前缀 + D05 动作段 + 用户要求的构图
状态：扩展动作参考；对应图片是整张九宫格，没有单独 D05.png
```

只要求查找时，交付对应图片链接、格子位置及所需提示词即可，不自动生图。要求生成时，将真实身份图片和选中的场景图片传给工具，并写明只参考哪一格、只生成一个角色；生成时不必先停下来等待用户再次确认。图片不可读时明确说明，不声称已核对。

共 6 张九宫格、54 个动作条目，另有 10 个文字场景模板。只读取当前任务需要的系列；新增图片不因入库自动获得用户认可。

## 通用前缀

复制以下前缀，再接任一动作或场景段即可使用；后续角色规范若有更新，以规范为准。

```text
以所附小天 Agent 九宫格为身份和画风参考，正面立绘用于核对细节。生成同一个小天：深棕蓬松微乱短发，深色猫耳与浅米色耳内，自然棕色圆眼，圆形黑框眼镜，深蓝卫衣，胸前米色咖啡杯与齿轮徽记，深灰工装裤，灰色运动鞋，角色自身左腕有小型工具腕带。保持认可图的温暖手绘二次元风格、发丝细节、柔和纹理与服装质感，不改为扁平简笔或 3D。头身比例沿用参考；短颈自然连接下颌和肩膀，领口柔软，帽兜自然后垂。只生成下述指定动作，不复制九宫格，不增加其他人物或无关道具。手部结构自然，道具不穿手、不遮脸。默认无文字、无水印，浅米白背景；耳朵与动作所需手脚完整可见，四周留边。
```

## 九宫格动作

以下按原图从左到右、从上到下编号；文字定义供新生成使用，不宣称精确复刻每个像素。

### A01 正面站立 · 基础介绍

```text
正面全身站立，身体重心稳定，双脚自然分开，双臂放松垂于两侧，双手自然展开。看向观众，闭嘴轻笑，亲切从容。人物居中，纯净背景，无道具；完整展示猫耳、鞋子和自身左腕腕带。
```

### A02 挥手 · 开场与结束

```text
正面全身，角色自身右手抬到脸侧，掌心朝向观众，五指自然分开，表现一次友好的挥手姿态；自身左臂自然下垂。开心微笑，可轻弯眼睛，手掌不挡住眼镜和猫耳。人物居中，无其他道具。
```

### A03 托腮 · 思考问题

```text
正面略侧身全身站立，自身右手轻触下巴，自身左前臂支撑右肘，左腕腕带位于真实左腕。视线看向画面右上方，眉毛轻抬，嘴巴自然闭合，表现认真思考而非焦虑。头部轻微倾斜，颈部不拉长；不加问号或文字气泡。
```

### A04 指向讲解 · 强调步骤

```text
人物放在画面左侧，身体与脸轻转向画面右侧，用自身右手食指指向画面右侧中部，视线跟随指尖，自身左手自然收在腰侧。微笑讲解，肩肘腕连接自然，手臂不遮脸；画面右侧留给后期内容，指尖前留出空间，不生成文字或白板内容。
```

### A05 阅读 · 文档与学习

```text
全身坐在简洁矮凳上，双脚自然落地，双手托住一本打开的书，书页位于胸口以下。眼睛看向书页，神情专注放松，书不遮脸，指尖与书页接触合理。书页只有少量示意线条，无可读文字，不增加书堆。
```

### A06 使用电脑 · 编码与实践

```text
全身盘腿坐着，笔记本电脑稳放腿上，双手自然放在键盘位置，视线看向屏幕，表情专注。电脑上缘不遮脸，腿脚关系清楚；电脑外壳素净，不额外复制胸口徽记，不生成可读代码或运行结果。
```

### A07 观察查找 · 检索与核实

```text
全身站立，自身右手持放大镜，自身左手持一张文档，放大镜位于文档附近，视线看向被检查的位置。道具放在脸侧下方，不用镜片遮住眼镜或整张脸。神情好奇认真，文档用几条短线表示内容，不写随机文字。
```

### A08 点赞 · 完成与鼓励

```text
正面全身，自身右手在胸侧竖起大拇指，其余手指自然弯曲，自身左臂放松。露出开心笑容，姿态稳定，徽记保持清晰。默认不加对勾或成功结果；仅在内容已确认完成时用作成功反馈。
```

### A09 摊手 · 信息不足

```text
正面全身，双前臂自然向两侧展开，双手掌心朝上，轻微抬眉，嘴巴微张，表现坦诚解释“尚不确定”的态度。肩膀放松，头部居中，不夸张耸肩或崩溃；不用文字气泡，保留两侧手掌完整。
```

## 扩展技术场景

场景默认横向 16:9，人物与道具共同解释一个概念；标签由文章或脚本核实后单独排版。默认是教学示意，不作为真实软件运行证据。

### S01 比较版本 · 核对冲突

```text
小天站在两张并排文档旁，自身左手持一张文档，自身右手指向另一张文档中的对应位置，目光认真对比，眉头轻皱。两份文档使用相同版式，仅一处用暖橙色标出差异。为后期版本标签留白，不预设哪份正确，不添加成功对勾。
```

### S02 排查日志 · 定位异常

```text
小天位于画面左侧，身体略前倾，自身右手指向右侧终端示意面板中的一行，自身左手自然收在身前，目光聚焦该行。其余日志用淡色短线示意，当前行用暖橙突出；真实错误信息后期叠加，不编造错误码或已修复结论。
```

### S03 选择工具 · 决定下一步

```text
小天站在打开的小工具箱旁，自身右手伸向箱内一件放大镜，自身左手扶住箱盖，目光看向所选工具。工具箱只保留放大镜与文档夹两个清晰对象，不让大量图标飞出。表现正在选择，不表现工具已经执行成功。
```

### S04 递交请求 · 工具调用边界

```text
小天位于左侧，自身右手把一张请求卡递向画面中央的校验台，自身左手放松，目光跟随卡片。校验台与右侧工具箱分开，卡片尚未到达工具箱；为后期流程箭头留白。用递交动作表达请求，不暗示模型直接操作真实系统。
```

### S05 等待授权 · 写操作前确认

```text
小天站在一个简洁确认面板旁，自身右手张开示意暂停，自身左手托住待提交文档，表情耐心。面板预留按钮区域但不写字，手指不按按钮；表现等待用户决定，不用成功状态或已解锁图标。
```

### S06 检索资料 · 查到相关内容

```text
小天站在低矮资料架旁，自身右手抽出一份文档，自身左手扶住另一叠资料，目光看向抽出的文档。仅该文档用柔和蓝色突出，其余资料低对比；表现检索命中，不把找到文档等同于答案已证实。
```

### S07 内容边界 · 识别提示注入

```text
小天站在外部文档与指令面板之间，自身右手用张开的手掌示意外部文档停留在资料区，自身左手指向独立的指令面板，表情认真平静。两区域在空间上分开，不把文档画成怪物；精确标签后期添加。此为信任边界隐喻，不声称所有注入已被自动拦截。
```

### S08 预算与停止 · 有限尝试

```text
小天位于画面左侧，注视右侧简洁调用计数面板，自身右手做停止手势，自身左手合上笔记本。面板的具体数值由任务提供并后期叠加，不随机生成倒计时。表情冷静，体现达到停止条件后结束尝试。
```

### S09 整理知识 · 归纳关系

```text
小天站在三张空白知识卡旁，自身右手将一张卡放到对应分组下，自身左手托住剩余卡片，视线跟随放置位置。只展示一次归类动作，卡片标题与关系线后期按真实内容排版；不默认所有主题都是树状结构。
```

### S10 展示结果 · 交付与复盘

```text
小天位于画面右侧，身体轻转向左，用自身右手张掌介绍左侧的结果面板，自身左臂自然放松，神情友好。面板留出主要展示区域，人物和手不挡内容。只有经核实的结果才添加完成标识；未验证结果保持中性展示。
```

## 按交付追加

- 单人素材：浅色背景、人物居中、完整动作轮廓；需要透明背景时明确要求真实透明通道并检查，不把棋盘格当透明。
- 文章插图：人物可从画高 25%–30% 尝试，按内容调整；人物动作指向具体对象，技术内容清晰优先，不把人物压成角标。
- 头像：1:1 头肩构图，直视观众，友好微笑，圆形裁切范围内保留猫耳与发梢，不加手持道具。
- 九宫格扩展：明确列出九个编号及行列顺序，同一头部尺度、同一画风、足够间距。未要求时不自动批量出图。

### 视频运动段

在动作段后追加“起始姿态 → 一次主要动作 → 停稳”，再给实际秒数与声音方式；不把静态姿态直接当动画。可复制示例：

```text
约 6 秒，固定镜头。前 1 秒小天看向观众，双手自然放松；随后 2 秒自身右手抬起指向画面右侧内容，目光跟随，肩膀轻微配合；最后 3 秒保持指向，仅有轻微呼吸和眨眼。头颈肩连接稳定，左腕腕带与徽记不变。无旁白，不做说话口型；技术文字后期叠加。
```

## 扩展九宫格素材索引

三张扩展图已生成并做整图目视检查，尚未单独取得用户逐图认可；只作为姿态与场景参考，默认身份仍以原认可九宫格为准。不是动画连续帧。编号按从左到右、从上到下排列。

用法：通用前缀 + 下表对应提示词 + 本次构图/交付要求。实际附上默认身份图及选中的扩展图，指定只生成该编号对应的一个人物；不用一次加载全部素材。图中道具徽记、装饰问号不作为固定身份，腕带被遮挡时不能据此推断换侧。

技术工作图为带透明通道 PNG；讲解互动与日常学习图为米白底 PNG，后两张不能直接当作透明贴图。正式合成前仍需检查透明图的边缘与残余像素。

## 程序员专题九宫格

D01–D09 与 R01–R09 为新增静态场景素材，按从左到右、从上到下编号，使用本文件通用身份前缀加下表动作段即可生成。已做整图目视检查，尚未取得用户逐图认可；原认可九宫格仍是身份基准。

这些图片用于角色动作与技术情境，不是运行证据或严谨机制图。屏幕图标有示意性：联调格未完整展示请求/响应双向链路，发布格的上箭头不能直接解读为真实部署方向，回滚格也未标明版本。用于技术说明时按事实重绘流程和标签；代码审查等姿势不锁定惯用手，但腕带始终在自身左腕。
