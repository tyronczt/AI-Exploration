# 提示词、动作与验收

## 提示词组装

每次先读取 character.md。身份描述从该规范取用，以下模板不是第二份角色设定。花括号是使用时需要按真实任务填写的字段，不得原样交给生成工具。

```text
任务：{生成或编辑的单人物素材及用途}。
参考：{真实图片与角色；逐张说明身份、风格或姿态用途}。
保持：依据当前角色规范与认可参考，保持脸型、比例、发型、猫耳、眼镜、服饰、徽记及腕带侧别。
变化：{本次唯一或主要动作、对象、方向、表情、道具}。
表达：{标准手绘版或信息图简化版}，与指定风格参考一致。
构图：{景别、朝向、占比、留白、尺寸、背景}。
文字：默认不加文字、随机符号、其他品牌徽章。
交付：{格式；如需透明，要求真实透明通道}。
检查：{此次易出错的身份或动作细节}。
```

没有用户专用母版时，直接依据包内默认角色规范和图片生成，不要求用户先建母版。外部构图图只借排布，角色身份从小天规范和相应参考取得。

## 动作选择

| 语义 | 动作示例 | 注意 |
|---|---|---|
| 观察 | 放大镜检查指定文档或对象 | 道具不遮眼镜与脸 |
| 思考 | 托腮、看向待解释对象 | 不自动添加文字气泡 |
| 讲解 | 一手指向指定位置，目光配合 | 明确自身哪只手及画面方向 |
| 使用工具 | 打开工具箱或操作终端 | 不把多个复杂动作塞进一帧 |
| 核对反馈 | 比较两份记录、点头或轻皱眉 | 结果未知时不加成功对勾 |
| 诚实未知 | 温和摊手、疑问表情 | 不呈现无能或崩溃的夸张表情 |
| 成功与结束 | 竖拇指或挥手 | 根据任务选择一个主要动作 |

## 三种常见请求

**只做方案**：交付身份依据、动作与构图说明、完整提示词、待定项；不调用生图工具。

**初次正面母版**：采用标准手绘版，正面全身、手臂自然、浅色无干扰背景。保持耳朵与鞋子完整，以便判断比例、徽记和自身左侧腕带。先生成单个角色，不强制多视图同画布。新设计细节标为候选。

**修正腕带**：以待编辑图为基础，仅将腕带修正到自身左侧，保持脸型、表情、姿态、服装和背景。检查原处残影、袖口与手部变形。生成工具可能连带改动其他部位，需重新查看整图。

## 视觉验收

逐项写“通过 / 有缺陷 / 无法判断”，没有测量依据不输出相似度百分比。

1. 身份：对照参考，脸型、头身比例、头发、猫耳、眼镜是否稳定；徽记是否变形或被替换；腕带是否保持解剖侧。
2. 动作：指向对象与视线正确；手脚无增生、融合或不合理遮挡；道具数量与需求一致。
3. 表达：仍是同一手绘角色；简化细节不改变比例；没有意外写实化、3D 化或额外品牌文字。
4. 素材：尺寸和裁切符合需求；耳朵、手或脚的裁切是否符合景别；声称透明时检查实际 alpha，而非白底或棋盘格。
5. 应用：文章场景不遮挡标签和连线；视频静态素材保留需要的动作空间。未生成视频时不宣称连续帧或口型稳定。

身份缺陷优先修复。局部修复仍反复漂移时，回到最近的合格参考、减少同时变化的项目，或报告工具限制；不悄悄接受改头换面的结果。

## 输出记录

任务目录保留图片及一份简短 Markdown 记录：角色版本、用途、实际参考路径与角色、实际发送的提示词、生成工具（已知时）、状态、验收缺陷及后续反馈。最终回答提供实际文件链接，并区分“已生成”“已检查”“用户认可”。不把结构校验当视觉验收。
